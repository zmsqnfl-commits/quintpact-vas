VAS 2.13.0 — 처음에는 이것만 하세요
====================================

처음 시작하기
-------------
1) GitHub의 Code → Download ZIP 또는 릴리스의 VAS-2.13.0-windows.zip을 내려받습니다.
2) ZIP을 새 폴더에 전체 압축 해제하고, 첫 대화 세션을 만들기 전에 프로젝트 이름으로 바꿉니다.
3) project-layout.json, src/, ui/가 들어 있는 폴더 자체를 Codex에서 열거나 그 폴더에서 Claude Code를 시작합니다.
4) "이 폴더를 프로젝트로 지정하고 색인해줘"라고 말하세요.
5) AI가 start로 현재 앱·저장 지시·세션을 읽습니다. 이전 앱 이야기가 있고 새로 만들지 옮길지 불분명하면 그 선택만 묻습니다.
   이전 이야기가 없는 빈 앱은 사용자와 첫 기능을 확인하고, 기존 앱은 바꿀 기능을 확인합니다.
   답을 이어서 정리하고 "이 조건으로 만들어줘"라고 하면 합의한 작업을 준비하고 구현과 검사로 진행합니다.
   확인한 문구 하나를 바꾸는 작은 수정은 실제 검사 후 간단한 finish로 기록합니다. 이전·데이터·배포 작업은 세션을 준비한 뒤 진행합니다.
   구간 끝에는 finish가 실제 검사와 다음 행동을 기록해 다시 읽습니다. 같은 폴더를 여는 새 호스트는 vas-state/progress/의 최소 요약을 볼 수 있습니다. 사용자가 명령을 입력할 필요는 없습니다.
   구조만 보고 싶다면 "폴더 구조만 알려줘"라고 요청하세요.

새 앱의 코드·자산·의존성 설정·컨테이너 설정·빌드 결과는 최상위 src/ 안에 둡니다. 앱 설치·실행·검사·빌드는 src/에서 합니다. ui/는 VAS 화면, scripts/는 명령, docs/는 안내입니다.
VAS의 기술 스택을 새 앱에 강제하지 않습니다. 실제 앱의 지침과 원본을 먼저 확인합니다.
GitHub 복제본, Code → Download ZIP과 Windows 프로젝트 ZIP은 같은 위치에서 앱을 시작합니다.
실행할 때는 앱 자체의 진입점과 명령을 사용합니다. 이미 만든 앱이면 기존 코드와 데이터를 보존합니다.

Windows 10/11과 PowerShell 5.1 이상을 사용합니다.
대화 설정·지시 CLI는 코딩 호스트에서 Python 3.10 이상을 실행할 수 있어야 합니다.
VAS는 Python이나 코딩 AI를 포함하지 않습니다.

작업 요약을 직접 읽으려면 vas-state/progress/에서 가장 높은 완료 판본(.ok)의 같은 번호 .md 파일을 여세요. 예를 들어 000001.ok에 대응하는 파일은 000001.md입니다.
준비한 작업의 목표·완료조건과 기록된 결정·남은 일·검사를 볼 수 있습니다. 에이전트가 생성하므로 사용자가 양식을 만들 필요가 없습니다.

화면에서 프로젝트 지시 수정하기
------------------------------
Run-VAS-System.bat를 더블클릭해 VAS 설정 화면을 엽니다.
프로젝트 작업 지시에 기능·제약·확인할 조건을 적고 저장 성공을 확인하세요.
그다음 코딩 채팅에서 "저장한 지시로 진행해줘"라고 하면 됩니다.

화면과 에이전트는 루트의 VAS-PROJECT-PROMPT.json을 함께 사용합니다.
AI가 첫 요청·재개·구현·위임 전에 최신 지시를 읽습니다.
저장만으로 AI가 자동 실행되거나 진행 중인 대화가 바뀌지는 않습니다.
예전에 복사한 프롬프트도 자동 갱신되지 않으므로 최신 인계를 다시 준비합니다.
다른 화면의 저장과 충돌하면 초안을 유지하며 최신 내용을 읽어 비교합니다.
현재 대화의 명시적인 요청과 상위 지침이 저장 문구보다 우선합니다.

이 파일은 프로젝트와 함께 옮길 수 있습니다. 비밀값·연락처·개인 경로는 넣지 마세요.
PC 전용 세션과는 별개라 세션 생성 전에도 읽을 수 있습니다.
구현 전에 AI가 실제로 조회한 지시 판본과 기존 세션을 확인하고, 합의한 설정 저장 후 다시 읽어 인계를 준비합니다.
VAS 설정 화면을 여는 것은 앱 실행이 아닙니다. 앱 화면은 앱 자체의 실행 방법으로 확인합니다.

에이전트와 구현·검증 이어가기
----------------------------
AI가 실제 작업 대상, 요청, 완료조건과 구현에 필요한 질문을 정리합니다.
이미 정한 내용을 다시 입력하거나 지침 파일을 읽으라고 지시할 필요는 없습니다.
주 실행자가 최신 설정으로 인계를 준비하고 실제 앱 원본을 읽어 구현·검증합니다.
독립적인 작업이 유용하고 위임 도구가 있으면 범위를 정해 역할을 맡깁니다.
도구가 없으면 주 실행자가 순서대로 작업하며 실행하지 않은 역할을 실행했다고 하지 않습니다.

같은 PC와 같은 설치 위치에서 "이어서 해줘"라고 하면 저장한 설정과 최신 진행 요약을 읽습니다.
현재 파일·변경 내용·검사 근거를 다시 확인해 남은 작업으로 이어갑니다.
실패·미실행·근거 불일치·관련 파일 변경은 구분하고 필요한 검사만 보완합니다.
작업 구간 끝에는 실제 다음 행동을 저장하고 다시 읽어 확인합니다.
사용자는 기록용 JSON을 직접 만들 필요가 없습니다.
호스트의 저장소 접근이 막히면 미저장·미복원 사실을 알리며 권한을 자동 변경하지 않습니다.
저장된 성공 보고, VAS 평가와 사용자 직접 확인은 서로 다릅니다.
원래 자동검사만 필요한 작업에 새 수동 확인이나 승인을 임의로 추가하지 않습니다.
자세한 흐름: docs/CHAT-EXECUTION.md

디자인은 필요한 요소만 참고하기
------------------------------
"이 작업의 디자인 화면 열어줘"라고 하면 연결된 로컬 스튜디오에서 비교할 수 있습니다.
선택 뒤 "대화 설정에 저장"을 눌러야 연결한 작업에 반영됩니다.
샘플 열기만으로 저장되지는 않으며 독립 HTML·GitHub Pages는 개인 세션과 연결되지 않습니다.
기존 앱은 디자인 유지가 기본이고 부분 변경은 지정한 화면·요소에만 적용합니다.

샘플에서는 글꼴·색상·배치·이미지 표현·여백을 참고합니다.
요금제·결제·로그인 같은 샘플 기능은 실제 요청에 필요할 때만 만듭니다.
참고 이미지는 코딩 채팅에 실제 파일을 첨부하세요. VAS 폼의 파일 개수만으로 내용은 전달되지 않습니다.
기본 디자인 분석 스킬이 관찰·추정·앱 적용 위치·화면 확인을 연결합니다.
별도 스킬 설치·Obsidian 연결·새 API 키는 필요하지 않습니다.
VAS가 이미지 자체를 분석하거나 AI에 업로드하지는 않습니다. 코딩 호스트의 보기 도구를 사용합니다.

PC·모바일 폭과 320 CSS px, 빈 화면·긴 한글·큰 숫자를 실제 화면에서 확인합니다.
글꼴 선언과 실제 로딩, 라틴·숫자와 한글 대체 글꼴을 구분합니다.
로컬 글꼴이 필요하면 필요한 파일과 OFL 라이선스를 앱 자산으로 함께 복사합니다.
작은 글자와 placeholder 대비, 키보드·입력·주요 동작·새로고침도 확인합니다.
브라우저 폭 조절은 실제 휴대전화 검사와 다릅니다. 확인하지 못한 항목은 남겨 둡니다.
자세한 안내: docs/DESIGN-ANALYSIS.md

이전 버전에서 옮기기
--------------------
기존 실행을 종료하고 설치 폴더·앱·사용자 파일을 먼저 백업합니다.
2.13.0은 새 폴더에 풀고 기존 앱 위에 압축을 풀어 덮어쓰지 않습니다.
앱의 src/·자산·설정·데이터·프로젝트 지시 파일은 보존합니다.
실제 앱 소유 파일만 새 프로젝트로 옮기고 지침·설정 충돌은 비교해 유지합니다.
이전 VAS 도구의 src/를 앱 소스로 잘못 복사하지 마세요.
새 폴더에서 새 대화를 열어 현재 원본과 지시를 확인한 뒤 작업을 연결합니다.
앱과 지시 저장을 확인할 때까지 기존 설치를 보관하세요.

경로나 PC가 바뀌면 PC 전용 세션·진행 기록·대상 연결은 자동 이전되지 않습니다.
프로젝트 지시나 공개 설정만 복사해도 개인 연결 기록이 복원되는 것은 아닙니다.
설정·진행 요약·실행 기록은 앱 파일 백업이 아닙니다.
자세한 안내: docs/MIGRATION.md, docs/CHAT-STATE.md

기존 화면 인계 방식
-------------------
새 프로젝트: 요구사항·완료조건 → 필요한 디자인 → 최종 확인 → 프롬프트 복사
기존 앱: 실제 폴더 → 작업·완료조건 → 디자인 유지 또는 변경 범위 → 프롬프트 복사
복사한 프롬프트는 실제 앱 폴더를 연 코딩 채팅에 붙입니다.
GitHub 소스와 Windows 프로젝트 ZIP에서는 폴더 전체를 열고 src/에 구현합니다.
독립 폼이나 외부 앱용 인계에도 역할 지침이 포함됩니다. 다른 앱을 지정했다면 해당 앱의 폴더를 열고 그 앱의 지침·진입점·검사 명령을 사용합니다.
설정 보관이 필요할 때만 VAS-AI-HANDOFF.json을 함께 저장합니다.
READY는 인계 준비 완료이며 앱 구현이나 테스트 완료가 아닙니다.

로컬 서버가 시작하지 못한 제한 모드에서는 브라우저 초안·디자인 저장과 프롬프트·JSON 내보내기를 사용할 수 있습니다.
Windows 폴더 선택창·프로젝트 지시 파일 저장·대화 동기화·Windows 작업 기억은 사용할 수 없습니다.
프로젝트 지시를 저장했다고 표시하지 않으며 폴더 위치는 직접 입력합니다.

기억과 개인정보
---------------
작업 기억은 선택 기능이며 대화 설정과 별개입니다.
Windows 서버는 별도 동의를 확인하고 누적 10,000건·8 MiB를 넘는 저장을 거부합니다.
기억을 끄는 것과 삭제는 다르며 정상 크기의 기존 기록은 끈 뒤에도 조회·내보내기·삭제할 수 있습니다.
이전 초과 저장소는 자동 삭제하지 않습니다. 복구 방법은 docs/OPERATIONS.md를 참고하세요.
절대 경로·비밀번호·API 키·연락처·기억 원본을 공유 설정에 넣지 않습니다.
실제 프로젝트 분석·코드 수정·실행은 코딩 호스트가 사용자 요청 범위에서 수행합니다.
