# 화면 검수표

사용자에게 보내기 전에 만든 사람이 직접 한다. 소스 코드, 검사 통과 메시지, 도구의 성공 응답은 검수가 아니다.

## 준비

- 앱을 실제로 실행해 화면을 연다. 화면을 캡처할 수 있으면 캡처해서 본다.
- 폭 세 가지: 넓은 화면, 좁은 화면(390px 안팎), 가능하면 320 CSS px.
- 상태 세 가지: 비어 있을 때, 보통 내용이 있을 때, 긴 한글과 큰 숫자가 들어 있을 때.
- 주요 동작을 직접 해 본다. 입력, 저장, 새로고침, 키보드 이동.

## 2초 질문

화면을 2초만 보고 답한다. 답이 바로 나오지 않으면 구도나 위계가 약한 것이다.

- 무슨 화면인가.
- 가장 중요한 내용은 어디에 있는가.
- 어디를 누르면 되는가.

## 다섯 요소

| 요소 | 볼 것 |
| --- | --- |
| 글꼴 | 제목과 본문의 차이가 한눈에 보이는가. 실제로 그려진 글꼴이 정한 글꼴인가. 가장 작은 글자를 읽을 수 있는가 |
| 색 | 강조색이 한두 곳에만 쓰였는가. 글자와 배경의 대비가 충분한가. 색 없이도 상태를 알 수 있는가 |
| 배치 | 첫 화면에 핵심 내용과 주요 행동이 있는가. 줄과 칸의 시작선이 맞는가. 좁은 화면에서 순서가 자연스러운가 |
| 이미지 | 내용과 관계가 있는가. 잘리거나 찌그러지지 않았는가. 이미지가 없을 때 자리가 무너지지 않는가 |
| 여백 | 관련 있는 것끼리 가깝고 다른 묶음과 떨어져 있는가. 같은 종류의 간격이 같은 값인가 |

계획(`DESIGN.md`)이나 참고 분석이 있으면 각 줄을 그것과 대조한다.

## 가장 약한 세 곳

잘된 곳을 찾지 말고 가장 약한 세 곳을 찾는다. 고친 뒤 다시 연다. 세 곳을 찾지 못했다면 화면을 충분히 보지 않은 것이다.

## 스스로 고칠 기본 결함

- 잘린 글자, 겹친 요소, 화면 밖으로 나간 내용
- 오탈자, 확정 문구와 다른 글자
- 한두 픽셀 어긋난 정렬, 들쭉날쭉한 간격
- 읽기 어려운 대비, 너무 작은 글자
- 문장 끝 한두 글자만 남은 줄
- 좁은 화면에서 누르기 어려운 작은 버튼(44px 안팎이 기준)
- 포커스 표시가 없는 버튼과 입력창

## 자주 생기는 원인

- 가로나 격자로 나열한 칸의 내용이 넘친다: 그 칸에 `min-width: 0` 또는 `min-height: 0`을 준다.
- 높이를 고정한 상자에서 긴 글이 잘린다: 고정 높이 대신 최소 높이를 쓴다.
- 좁은 화면에 가로 스크롤이 생긴다: `100vw` 폭이나 고정 폭 요소를 찾는다.
- 아래에 고정한 막대가 내용을 가린다: 본문 아래에 그 높이만큼 여백을 준다.
- 이미지가 찌그러진다: `aspect-ratio`와 `object-fit`을 정한다.

넘친 내용을 `overflow: hidden`으로 숨기거나 글자를 지워서 통과시키지 않는다.
