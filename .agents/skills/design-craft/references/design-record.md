# 디자인 기록 양식 (DESIGN.md)

앱 폴더의 `DESIGN.md` 한 장에 적는다. 다음 대화의 에이전트와 사용자가 읽는 파일이다. 한 화면 분량을 넘기지 않는다. 비밀값·연락처·개인 경로는 적지 않는다.

이미 `DESIGN.md`나 토큰 파일이 있는 앱은 그 파일의 형식을 유지하고 빠진 항목만 보탠다.

```text
# 디자인 기록

## 무엇을 위한 화면인가
- 주제:
- 쓰는 사람:
- 가장 중요한 한 가지 일:

## 정해진 것 (다시 묻지 않는다)
- 사용자가 정한 것: 말한 그대로 적는다. 없으면 "없음"
- 참고: 실제로 본 이미지·화면과 거기서 가져온 관계. 없으면 "없음"
- 바꾸지 않을 것: 유지하기로 한 화면·요소

## 색
| 역할 | 값 | 쓰는 곳 |
| --- | --- | --- |
| 배경 | #...... | |
| 표면 | #...... | 카드, 입력창 |
| 본문 | #...... | |
| 보조 글자 | #...... | 설명, 날짜 |
| 강조 | #...... | 주요 버튼, 선택 표시 |
| 상태 | #...... | 오류·성공 |

## 글꼴
- 제목:
- 본문:
- 숫자·표: (필요할 때만)
- 크기 단계와 굵기:

## 배치
- 넓은 화면:
- 좁은 화면:

## 기억될 한 가지

## 확인한 것과 남은 것
- 날짜 · 본 화면 크기 · 고친 것 · 아직 못 본 것
```

## 적는 법

- 값은 실제 코드에 쓴 값과 같아야 한다. 코드를 바꾸면 이 파일도 고친다.
- “깔끔하게”, “고급스럽게” 같은 형용사만 적지 않는다. 어느 요소를 어떻게 했는지 적는다.
- 사용자가 정한 것과 에이전트가 고른 것을 구분한다. 에이전트가 고른 것은 사용자가 바꾸라고 하면 바로 바꾼다.
- 참고 이미지에서 추정한 글꼴 이름이나 색상값을 원본의 정확한 값처럼 적지 않는다.
- 계획과 달라진 부분은 지우지 말고 바뀐 값과 이유를 한 줄로 남긴다.
