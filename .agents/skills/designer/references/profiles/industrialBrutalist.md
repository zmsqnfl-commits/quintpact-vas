# Industrial Brutalist

- Scope: borrow visual elements only. Features, routes, data and actions come from the user request and existing app, not this sample. Add sample functionality only when explicitly requested; preserve required functionality even when the sample lacks it.
- Composition: use a strong heading, disciplined grid and a headline/graphic split only where expressive content fits. Operational screens begin with their required controls and data; do not add a production list or portfolio from the sample.
- Hierarchy: bold display at 3-4 times body size when appropriate, secondary headings at 1.5 times and mono detail at 0.8-0.875 times. Keep general Korean UI text on a readable sans stack.
- Structure: confirmed border width and radius, one primary accent and padding as a section unit. Align existing labels and content across rows without inventing indices or metadata.
- Focal point: strong typographic or geometric contrast tied to the actual subject. Pair a larger heading with calm readable body copy and functional labels.
- Controls: requested controls need clear pressed, focused and disabled states. Hard shadows and physical translation are optional and must respect confirmed tokens and reduced motion.
- Responsive: stack expressive splits, reduce display scale, wrap secondary content and retain 44px touch targets at 320px. Do not shrink desktop grids below legibility.
- Preserve user tokens and references. Inspect actual desktop/mobile alignment, contrast, wrapping and requested interaction feedback before handoff.
