# Redesign Guard

- Scope: borrow visual elements only. Features, routes, data and actions come from the user request and existing app, not this sample. Add sample functionality only when explicitly requested; preserve required functionality even when the sample lacks it.
- Start with the actual screen, its main task and working routes. Record information order and component states before changing appearance. Reference features do not authorize new behaviour or removal of existing behaviour.
- Establish one page heading, clear secondary headings, body copy and quiet labels. Existing fonts and confirmed size tokens are the base; fix inconsistent weights and leading.
- Consolidate spacing around confirmed padding. Align labels, controls and content edges; remove redundant containers only when their grouping has no meaning.
- Strengthen primary action, selection and focus visibility. Preserve useful secondary actions and existing empty, loading, error and disabled behaviour.
- Choose one visual detail from the product or reference. Do not import an unrelated portfolio, metric dashboard, navigation model or sample feature set.
- Preserve saved data, routes, component APIs, framework, colours and confirmed tokens. Explain accessibility-related token conflicts before changing values.
- Compare before/after at 320/390px and desktop. Check real content, long names, overflow, keyboard order and the unchanged primary workflow; scope final claims to evidence.
