# Minimalist Utility

- Scope: borrow visual elements only. Features, routes, data and actions come from the user request and existing app, not this sample. Add sample functionality only when explicitly requested; preserve required functionality even when the sample lacks it.
- Composition: use quiet alignment and a readable main content region with tools near the content they affect. Prose may use a document-width column; do not invent breadcrumbs, notes or a document editor when the task does not need them.
- Hierarchy: body at confirmed base size with 1.7 leading, heading at 2-2.75 times, secondary headings at 1.25-1.5 times and quiet labels at 0.8-0.875 times. Limit prose to about 60-72 characters per line.
- Rhythm: confirmed padding between sections, half that within connected rows. Structure actual content with alignment and subtle rules instead of boxing every paragraph or value.
- Details: restrained icons and distinct emphasis for existing navigation, links and primary actions. Names, dates and indices must come from actual requirements or data, not a sample.
- Controls: apply native semantics and visible focus to requested actions. Search, editing and disclosure are not automatically included; if required, show clear empty, saved or error feedback.
- Responsive: compact navigation if present, fluid reading regions and 16-24px side gutters. Wrap long content and move secondary labels onto new lines.
- Preserve confirmed colours, radii, framework and fonts. Check reading comfort, text selection, actual keyboard actions and 320/390px plus desktop renders.
