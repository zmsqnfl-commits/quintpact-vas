# 디자인 실행 지침

- 먼저 실제 참고 이미지·서비스와 기존 UI를 확인한다. 첨부되지 않은 파일의 내용을 추정하지 않는다.
- 참고 이미지나 화면이 있으면 전달된 디자인 분석 지침을 따른다. 다섯 요소의 실제 관찰·불확실성·앱 적용 위치를 연결하고, 원본을 확인하지 못한 항목은 미확인으로 반환한다. 단순 버그 수정이나 기존 디자인 유지에 새로운 스타일 분석을 강제하지 않는다.
- 스타일보다 작업의 디자인 변경 범위를 먼저 확인한다. 기존 유지에서는 필요한 UI만 기존 규칙으로 추가하고 전역 색상·폰트·레이아웃을 바꾸지 않는다. 부분 수정은 지정한 화면·요소·속성에 한정한다. 전체 리디자인도 데이터 삭제·기능 변경 권한이 아니다.
- 사용자 요청·기존 프로젝트 규칙·활성 디자인 토큰을 기준으로 허용된 범위에서 선택한 프로필을 적용한다. 색상·간격 변경으로 프로필을 바꾸지 않는다.
- 선택 프로필의 본문이 인계에 있으면 읽는다. 여러 프로필을 한꺼번에 섞지 않는다.
- 샘플·프리셋·프로필은 타이포그래피·색상·배치·이미지 표현·여백의 참고다. 요금제·결제·로그인·쇼핑·공연 목록 등 샘플 기능과 문구·업종·데이터·페이지 목록은 요구사항이 아니다. 최신 사용자 요청·저장한 프로젝트 지시·완료조건으로 기능을 정하고, 과거 디자인 지침이 기능 추가를 명령하더라도 요청 밖 기능은 넣지 않는다. 사용자가 요청한 결제·요금제 등은 그대로 구현한다.
- 구현 전에 선택한 디자인 요소를 실제 앱의 어느 화면·요소에 적용할지 짧게 연결한다. 예: 요금표의 정렬·구분선·여백은 재고 행에 적용할 수 있지만 요금제 선택기는 만들지 않는다. 원형 그래픽의 비율·색상은 가져올 수 있지만 공연 일정이나 음반 내용은 복제하지 않는다. 불필요한 샘플 영역은 생략하고 빈 가짜 기능으로 채우지 않는다.
- 작업에 맞는 화면 구성, 글자 크기 단계, 간격, 색상, 반응형, 버튼·입력의 기본/포커스/비활성/오류 상태를 구체적으로 정한다.
- 기존 프레임워크·컴포넌트·폰트 자산을 유지한다. 새 작업의 기술은 요구사항으로 선택하며 VAS 구현 언어를 강제하지 않는다.
- 확정 토큰을 CSS 변수 또는 프로젝트의 토큰 파일에 적용한다. 접근성 때문에 토큰 수정이 필요하면 이유와 변경값을 알린다.
- 참고 자료가 없는 시각 작업은 사용 가능한 이미지 도구로 시안을 만들거나 핵심 화면을 구현해 구도를 확인한다. 도구 사용·이미지 생성을 했다고 꾸미지 않는다.
- 구현 후 실제 브라우저에서 핵심 화면을 작은 화면과 큰 화면으로 확인한다. 참고 화면과 캡처를 비교해 계층·배치·타이포·색·간격·넘침·상태 차이를 수정한다.
- 화면과 동작을 요청·완료조건에 대조해 샘플에서 따라온 불필요한 기능이 없는지도 확인한다. 디자인 일치와 기능 범위 준수를 따로 보고한다.
- 최종 인계는 적용한 토큰/파일, 확인한 화면과 크기, 남은 차이로 작성한다. 브라우저 사용이 불가능하면 시각 검증 미실행을 명시한다.
- 이 스킬은 별도 에이전트를 자동 생성하지 않는다. 실행 도구가 제공되는 경우에만 실제 위임하고, 그렇지 않으면 현재 에이전트가 수행한다.

## VAS 프로젝트에서 추가로 확인할 사항

- VAS 프로젝트에서 참고 이미지를 분석할 때에는 `.agents/skills/design-analysis/SKILL.md`를 적용한다.
- VAS에서 선택 프로필의 정본을 확인할 때에는 `.agents/skills/designer/references/profiles/<프로필키>.md`를 읽는다.
- VAS의 선택 글꼴은 `ui/assets/fonts/`의 파일·라이선스와 `ui/design-collection.css`의 선언을 확인한다. 필요한 자산과 라이선스만 앱으로 복사하고 앱의 실행 경로는 앱 자산을 가리키게 한다.
- 세션 작업에서는 전달된 revision·인계 ID와 허용 범위를 유지한다. 세션을 직접 저장하지 않고 토큰 변경 제안·실제 확인 결과를 주 실행자에게 반환한다. 저장된 사용자 지정 값을 지원하지 못하면 다른 스타일로 대체하지 말고 차이를 알린다.
- work 작업에서는 실제 변경 파일·확인 명령과 종료 코드·조건별 결과·미확인 화면을 반환한다. 호출 ID나 검증 성공을 추정하지 않으며, 지문 관찰과 기록 저장은 주 실행자가 `docs/CHAT-WORK.md`에 따라 수행한다.
