# 복잡한 설계 비교

신규 아키텍처, 기술 이전, 다수 접근법의 성능 개선처럼 선택의 영향이 큰 경우에 사용한다.
1. 원본을 읽고 비교할 관점과 검증 조건을 정한다.
2. 실제 서브에이전트 도구가 있고 위임이 적절하면 분리된 탐색을 호출한다. 그렇지 않으면 현재 대화에서 대안을 비교하며 독립 탐색이라고 부르지 않는다.
3. 인터페이스·유지보수·성능·회귀 위험으로 대안을 비교하고 근거가 있는 설계를 선택한다.
4. 사용자 승인 범위를 벗어나는 변경만 확인한다. 승인된 범위는 `.agents/workflows/dev-cycle.md`의 구현·검증 단계로 이어간다.
