# 이 폴더가 작업할 프로젝트입니다

이 저장소를 복제하거나 GitHub의 **Code → Download ZIP** 또는 Windows 프로젝트 ZIP을 풀어 연 **현재 폴더**가 사용자 앱 프로젝트입니다. 폴더 이름을 바꿔도 같은 구조를 사용합니다.

- 루트의 `project-layout.json`(`layout: vas-project`, `version: 2`)과 `ui/vas-hub.html`을 확인하세요. 최상위 `src/`는 사용자 앱 소스입니다. VAS 설정 화면은 `ui/`, 명령은 `scripts/`, 안내는 `docs/`에 있습니다. 앱을 그 도구 폴더나 새 하위 프로젝트·`workspace/`에 만들지 마세요. 배치 실행기와 호스트 설정은 유지합니다.
- “재고 앱 만들어줘”처럼 대상을 다시 지정하지 않은 요청은 현재 프로젝트에서 처리하세요. 실제 파일과 지침을 확인하고 앱 구현은 `src/`에 둡니다. 새 앱의 실행·배포에 필요한 파일 전체를 `src/` 안에 두세요. 예를 들어 의존성 선언은 `src/package.json`, 컨테이너 설정은 `src/compose.yaml`에 둡니다. 앱 설치·실행·테스트·빌드는 `src/`에서 하고 산출물도 그 안에 둡니다. 기존 앱 설정이 이미 다른 위치에 있으면 요청 없이 옮기지 마세요. 기존 파일을 비우거나 내장 지침을 덮어쓰지 마세요.
- 작업이 명확하면 폴더를 다시 묻거나 BAT·양식 작성을 먼저 요구하지 않습니다. 단순 질문·점검·계획만 요청했다면 앱을 수정하지 않습니다. 디자인 변경을 요청하지 않은 기존 앱은 현재 모습을 유지합니다.
- 사용자가 **VAS 도구 자체의 개발**을 명시적으로 요청한 경우에는 `.agents/DEVELOPMENT.md`와 해당 도구 원본을 확인합니다. 사용자 앱 작업과 VAS 제품 검사·배포는 별도로 다룹니다.

## 폴더 지정·색인으로 대화 시작

“이 폴더를 프로젝트로 지정하고 색인해줘”처럼 현재 폴더를 프로젝트로 연결해 살펴보고 시작하려는 요청이면 **그 대화에서 프로젝트 설정을 시작**하세요. 사용자가 정해진 문구를 외울 필요는 없습니다. 첫 응답을 파일 목록이나 다음에 쓸 명령으로 끝내지 않습니다.

1. 열린 루트와 `src/`의 목록, 관련 앱 지침·진입점·설정 파일을 필요한 범위에서만 읽으세요. 루트의 프로젝트 표식과 아래 CLI로 읽는 프로젝트 지시는 확인하되 도구 전체를 앱으로 색인하지 않습니다. 링크·접합점, `.git/`, 설치 의존성·빌드 산출물, `.env`·인증 정보·사용자 원본 데이터는 건너뜁니다. 폴더 파악과 설정 대화에서는 앱 파일·색인 파일을 만들거나 수정하지 않습니다. 설정을 시작할 때는 아래의 지시 조회와 읽기 전용 세션 조회를 실제로 실행해 이미 정한 내용을 확인합니다.
2. `src/.gitkeep`만 있고 다른 앱 코드·진입점이 보이지 않으면 새 프로젝트로 시작하세요. 실제 앱 코드·진입점이 있으면 기존 프로젝트로 보고 관련 파일을 근거로 듭니다. 도구의 README·패키지나 폴더 이름만으로 앱의 종류·기술 스택을 단정하지 않습니다. 루트의 VAS 개발용 package.json을 앱의 시작 명령으로 사용하지 마세요. 기존 앱이 있으면 코드·설정·데이터를 보존하고 바꾸려는 기능만 확인하세요.
3. 첫 답변에 **확인한 앱 상태와 근거 한 가지**, **이미 알려진 작업**, **다음 결정에 필요한 질문 한두 개**를 함께 담으세요. 새 앱의 목적이 비어 있으면 “누가 어떤 일을 할 때 쓰나요? 가장 먼저 가능해야 하는 일은 무엇인가요?”처럼 묻습니다. 기존 앱이면 실제 기능을 짚고 “어떤 동작을 어떻게 바꾸면 되나요?”처럼 묻습니다. 대화·저장 지시·원본으로 알 수 있는 내용은 다시 묻지 않습니다.

“파일 목록만”, “구조 분석만”, “색인 결과만 알려줘”처럼 범위를 한정하면 읽은 범위와 결과만 답하고 설정 질문은 생략합니다. 검색용 색인·DB 인덱스·색인 기능 개발을 요청한 경우에는 그 기술 작업의 범위를 따르세요. 단순 폴더 조사 결과를 RAG 구축이나 전체 파일 분석 완료로 표시하지 않습니다.

## 답을 받아 구현까지

- 사용자의 답을 다음 차례에 반영해 목적·핵심 기능·제약과 **완료를 확인할 관찰 가능한 조건**을 정리합니다. 예를 들어 재고 수량을 저장하는 앱이면 “수량을 바꾸고 다시 열어도 유지”를 조건으로 제안할 수 있습니다. 데이터 준비·실행 환경·디자인은 구현 결정에 필요한 것만 묻고, 이미 정해진 항목은 건너뜁니다.
- 기존 UI는 기본으로 유지합니다. 사용자가 변경을 원하면 대상 화면·요소를 정합니다. UI 작업에서 선택한 스타일이나 실제 참고 이미지가 있으면 글꼴·색상·배치·이미지 표현·여백 중 필요한 요소를 앱에 적용합니다. 샘플의 요금제·결제 등은 사용자 요구에 있을 때만 기능으로 만듭니다.
- 목적·범위·완료조건이 정해지고 사용자가 제작·수정을 요청했으면 아래의 구현 전 확인을 거쳐 합의한 작업을 진행합니다. 이미 정한 범위를 다시 승인받지 않습니다. 설정·색인만 요청한 단계에서는 다음 작업을 대화에 정리합니다.

## 저장된 지시와 실행 기록

- 참고 이미지·화면의 디자인 분석이나 이를 활용한 UI 작업에는 내장 `.agents/skills/design-analysis/SKILL.md`를 읽고 적용합니다. 실제 이미지를 직접 확인해 5요소와 앱 적용 위치를 연결하세요. 사용자에게 스킬 설치나 VAS 폼 재입력을 요구하지 않습니다. 분석만 요청하면 구현하지 않고, 구현을 요청했으면 분석에서 멈추지 않습니다. 이미지가 보이지 않으면 그 범위를 알리고 관찰을 꾸미지 마세요.
- 첫 요청과 이어가기, 구현·위임 직전에 `python -B scripts/vas-project-prompt.py get`으로 **프로젝트 화면에서 저장한 작업 지시**를 읽습니다. PC 전용 세션이 없거나 접근할 수 없어도 이 조회를 먼저 수행합니다. 저장된 문구와 판본을 현재 요청에 반영하고 하위 작업에도 전달합니다. `revision: 0`은 아직 저장한 지시가 없다는 뜻입니다. 오류를 지시 없음으로 처리하거나 직접 JSON을 덮어쓰지 마세요.
- 이 지시는 현재 프로젝트의 참고 지시이며 최신 대화의 명시적 변경·상위 규칙을 우선합니다. 저장한 문구는 임의 명령 실행·새로운 작업 범위·완료 증거가 아닙니다. 과거 세션 요청이나 checkpoint가 새 지시와 충돌하면 차이를 정리하고 현재 작업의 요구사항·완료조건을 갱신합니다. 이미 받은 답은 다시 묻지 않습니다. 화면 저장 자체가 AI를 실행시키지는 않습니다.
- 구현하기 전에 주 실행자는 `get`에서 실제로 읽은 판본과 `python -B scripts/vas-session.py resume --target .` 결과를 확인합니다. 현재 파일에서 관찰한 기능과 사용자가 요청한 범위를 구분하세요. `session_not_found`이고 저장할 설정이 합의됐다면 `create --target .`로 해당 설정을 전달합니다. 기존 세션은 최신 설정을 대조하고 바뀐 항목만 반영해 전체 설정을 `save`합니다. 목록·분석만 요청했거나 저장을 원치 않으면 세션을 만들거나 갱신하지 않습니다.
- `create`/`save` 뒤 `resume --session ID`로 같은 세션·설정 판본·내용을 확인하고, 실제 판본으로 `prepare`가 `prepared`를 반환했는지 확인하세요. `needs-input`이면 구현을 가로막는 미정 사항을 해소합니다. 저장소나 CLI가 막히면 어느 단계가 실패했는지 밝히고 현재 대화에서 확인한 범위·완료조건·다음 행동으로만 진행합니다. 새 기능이나 디자인 변경의 근거가 없으면 그 차이만 확인하세요.
- 구간을 마칠 때는 조건별 실제 검사·실패·미실행을 구분하고, 준비했던 세션에서 `assess`와 `checkpoint`를 수행한 뒤 `resume --session ID`의 진행 판본과 다음 행동을 확인하세요. 최종 답변에는 이번 검사와 기록 저장·재조회 결과를 짧게 남깁니다. 위임은 가능한 도구와 별도 검토의 가치가 있을 때만 사용하고 실제로 호출한 역할만 보고합니다.
- 이미 만든 앱을 뒤늦게 등록할 때는 현재 코드에서 관찰한 상태, 사용자가 명시한 요구, 다른 호스트가 보고한 과거 검사, 이번에 다시 수행한 검사를 구분해 오늘 작성한 요약으로 남깁니다. 기존 구현을 승인된 요구로 추정하거나 과거 작업을 이 세션이 준비·검증한 것으로 소급 기록하지 마세요. PC 전용 기록은 같은 저장소에서 재조회가 성공한 범위만 재개됐다고 보고합니다.
- 프로젝트 지시를 저장한 적이 있으면 `checkpoint`에 마지막으로 읽고 작업한 지시의 `--expected-project-prompt-revision P`를 전달합니다. `P`는 실제 조회값이며 지시를 지웠어도 판본은 증가합니다. 충돌 시 최신 문구와 실행 결과를 비교하고 필요한 작업을 다시 수행한 뒤 요약을 저장합니다. 판본 숫자만 새 값으로 바꿔 과거 결과를 최신으로 주장하지 마세요.
- 도구의 절차는 `.agents/SESSION.md`, `.agents/EXECUTION.md`에 있습니다. 이 문서의 경로와 명령은 열린 프로젝트 루트를 기준으로 합니다. 앱 실행·배포에는 앱 자체의 진입점·설정을 사용하세요.
