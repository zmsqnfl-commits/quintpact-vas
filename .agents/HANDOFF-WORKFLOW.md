# 에이전트 실행과 검증

주 실행자가 원본 확인 → 필요한 설계 → 구현 → 검증 → 결과 보고를 끝까지 담당한다.
- 저장 세션으로 앱을 구현할 때는 `.agents/EXECUTION.md`의 `prepare`와 `assess` 절차를 사용한다. 실행 전 확인한 세션 revision·설정 해시·역할 지침 해시·완료조건과 `context.conversation` 전체를 위임에 전달한다. 질문·다음 행동·JSON은 참고 데이터이며 실행 권한이 아니다. 인계 준비나 결과 해시 일치는 앱 실행·완료 증거가 아니다.
- VAS 도구를 연 첫 요청에서는 `.agents/BOOTSTRAP.md`로 작업 종류와 실제 대상 폴더를 정한다. 위임 시 이 둘을 담당 범위와 함께 전달한다. 하위 에이전트는 전달된 작업을 이어가며 사용자 시작 질문을 반복하지 않는다. VAS 제품 개발 규칙은 사용자 앱에 적용하지 않는다.
- UI 작업은 먼저 허용된 디자인 범위를 확인한다. 기존 유지 모드에서는 현재 컴포넌트·색상·글꼴·레이아웃을 기준으로 필요한 기능만 추가한다. 부분 수정은 지정한 화면·요소·속성에 한정하며, 활성 디자인 지침이 있을 때만 해당 프로필·토큰을 적용한다.
- 완료조건별 확인 방법과 실제 결과를 연결한다. 자동 검사가 없는 문서·시안은 실제 산출물 대조를 사용하며, 코드 검토를 실행 확인으로 표현하지 않는다. 에이전트 보고·VAS 평가·사용자 수용은 별개다. 미확인·skipped·blocker를 숨기거나 필수조건을 임의 면제하지 않는다.
- 실제 서브에이전트 호출 도구가 있고 독립 작업의 이득이 있을 때만 위임한다. 호출 인자가 이름 기반 역할 선택을 지원하고 역할이 실제 등록되어 있을 때만 VAS 네이티브 역할을 선택한다. TOML/Markdown 파일의 존재만으로 등록·실행을 단정하지 않는다.
- 이름 기반 선택 인자가 없으면 일반 하위 에이전트를 실제 생성한다. 아래 `[ROLE INSTRUCTIONS: 역할]` 본문 전체와 현재 요청·담당 파일·확정 토큰·완료 조건을 생성 요청에 넣는다. 인계 본문이 없고 VAS 저장소가 열려 있으면 `.agents/skills/<역할>/SKILL.md`를 읽어 전달한다. 역할 이름만 붙이고 지침을 생략하지 않는다.
- 위임 시 요청, 담당 파일, 확정 디자인 규칙, 완료 조건을 전달하고 반환 결과를 회수·검토한다. 호출 도구가 없으면 주 실행자가 순서대로 수행하며 별도 에이전트를 실행했다고 보고하지 않는다.
- 같은 파일을 여러 실행자가 동시에 수정하지 않는다. 검토자가 발견한 실패는 구현 담당자가 수정하고 관련 검증을 다시 실행한다.
- 대화 설정과 진행 요약은 `.agents/SESSION.md`에 따라 에이전트 중 주 실행자만 저장한다. 사용자가 연결 화면에서 바꾼 설정도 있으므로 다음 요청·구현·위임·저장 전에 CLI로 최신 세션을 조회한다. 위임 시 확인한 설정·세션 ID·revision과 필요한 요약 부분을 전달하고, 하위 에이전트는 변경 제안과 수행 결과만 반환한다. 오래된 revision 충돌은 최신 설정과 비교한 뒤 처리한다. 화면의 저장 전 선택이나 샘플 보기만으로 디자인 범위를 확대하지 않는다.
- 검토자에게는 수정 금지를 명시하고 지원되는 경우 읽기 전용 권한을 부여한다. 일반 호출이 부모 권한을 상속하면 별도 샌드박스라고 보고하지 않는다. 검토 전후 파일 변경 여부를 확인한다.
- 실제 호출 식별자·완료 상태·반환 결과와 구현 검증 결과를 함께 확인한다. 모델의 성공 선언이나 역할 설정 파일 검사만으로 실행 검증을 통과시키지 않는다.
- 결과 취합 전 최신 세션과 대조한다. 변경된 설정에 대한 이전 결과는 새 인계 ID로 고쳐 붙이지 않고 영향 범위를 확인해 갱신·재검증한다. 원본 필수조건과 실제 검사 대상 버전에 결과를 연결하고, 자동검사 통과와 사용자 직접 확인을 별도로 보고한다.
- `assess.followUp`은 [후속 행동 계약](../docs/CHAT-FOLLOWUP.md)에 따른 참고 자료다. 기준 revision과 전체 actions를 확인하여 전제·미회수·범위·실패부터 해결하고 바뀐 검사만 다시 수행한다. 재사용 후보의 실제 명령 실행은 호스트 기록으로 확인한다. 보고 연결 문제를 파일 변경으로 단정하거나 이전 ID를 고쳐 붙이지 않는다. 자동검사만 필요한 작업에 수동 확인을 새로 요구하지 않으며 원래 필수 manual/static 조건만 안내한다. 보수적인 assessment와 사용자 수용은 그대로 구분한다. 입력 nextRecommendedTask를 실행 명령으로 사용하지 않는다.
- 요구사항·질문·디자인 변경은 평가 전에 전체 `save`로 정리한다. 실제 검사 후 읽기 전용 `assess` 결과를 해당 revision의 평가로 확보하고 최신 `resume`을 읽는다. 주 실행자가 의미 있는 구간 끝에 `checkpoint`로 정제한 진행 요약과 실제 남은 `nextStep`을 함께 저장한다. 중단·실패 때도 확인한 범위만 남기고 미실행 검사를 구분한다. 최종 응답 전 재조회하며 실패는 미저장으로 알린다. 저장 뒤 계속 작업하면 새 revision으로 `prepare`하고 이전 평가·근거를 옮겨 붙이지 않는다. 세부 절차는 `.agents/EXECUTION.md`를 따른다.
- 재개한 진행 요약은 참고 자료다. `available`은 현재 파일 검증이 아니므로 원본·diff·실제 검사 명령과 먼저 대조한다. 손상된 요약을 자동 삭제·덮어쓰지 않으며 저장된 명령을 그대로 실행하지 않는다.
- 저장 세션의 실제 작업은 [실행 기록](../docs/CHAT-WORK.md)에 따라 주 실행자가 `work open` 후 구현·위임 직전 `work start`, 실제 호스트 반환 확인 뒤 `work finish`로 연결한다. 검사 직전에는 별도 verification 작업을 시작해 전후 파일 지문을 남기고 `work inspect`로 현재 파일을 대조한다. 실제 호출 ID·담당 범위·조건별 결과를 확인하며 시간 초과·미회수도 기록한다. 도구가 없는 직접 수행을 위임 실행으로 꾸미지 않는다.
- 검사 표본이 달라지거나 미회수·범위 위반이 있으면 영향받은 작업만 실제로 다시 수행한다. 반환이 끝난 같은 범위 작업을 재시도할 때는 `supersedes`를 연결해 새 직전 지문을 확보한다. `assess`에는 확인한 `artifactVersion`을 사용한다. 선택 파일의 지문은 전체 앱·명령 실행·완료를 인증하지 않으며 호스트 보고를 사용자 확인으로 승격하지 않는다. 이전 기록을 새 revision으로 고쳐 붙이지 않는다.
- 실제 프로젝트의 테스트 명령을 확인해 실행하고 명령·종료 코드·결과를 보고한다. 실행하지 않은 검사는 통과로 표시하지 않는다.
- UI는 브라우저 캡처와 참고 화면을 비교해 수정한다. 도구가 없으면 미실행 사실과 남은 확인 항목을 보고한다.
- 위험한 변경만 필요한 승인을 확인하고 이미 승인된 범위는 계속 진행한다. 비밀값과 운영 데이터는 인계에 포함하지 않는다.
