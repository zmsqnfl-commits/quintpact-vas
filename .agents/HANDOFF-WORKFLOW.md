# 에이전트 실행과 검증

주 실행자가 원본 확인 → 필요한 설계 → 구현 → 검증 → 결과 보고를 끝까지 담당한다.
- 저장 세션으로 앱을 구현할 때는 `.agents/EXECUTION.md`의 `prepare`와 `assess` 절차를 사용한다. 실행 전 확인한 세션 revision·설정 해시·역할 지침 해시와 완료조건을 위임에 전달한다. 인계 준비나 결과 해시 일치는 앱 실행·완료 증거가 아니다.
- VAS 도구를 연 첫 요청에서는 `.agents/BOOTSTRAP.md`로 작업 종류와 실제 대상 폴더를 정한다. 위임 시 이 둘을 담당 범위와 함께 전달한다. 하위 에이전트는 전달된 작업을 이어가며 사용자 시작 질문을 반복하지 않는다. VAS 제품 개발 규칙은 사용자 앱에 적용하지 않는다.
- UI 작업은 먼저 허용된 디자인 범위를 확인한다. 기존 유지 모드에서는 현재 컴포넌트·색상·글꼴·레이아웃을 기준으로 필요한 기능만 추가한다. 부분 수정은 지정한 화면·요소·속성에 한정하며, 활성 디자인 지침이 있을 때만 해당 프로필·토큰을 적용한다.
- 완료조건별 확인 방법과 실제 결과를 연결한다. 자동 검사가 없는 문서·시안은 실제 산출물 대조를 사용하며, 코드 검토를 실행 확인으로 표현하지 않는다. 에이전트 보고·VAS 평가·사용자 수용은 별개다. 미확인·skipped·blocker를 숨기거나 필수조건을 임의 면제하지 않는다.
- 실제 서브에이전트 호출 도구가 있고 독립 작업의 이득이 있을 때만 위임한다. 호출 인자가 이름 기반 역할 선택을 지원하고 역할이 실제 등록되어 있을 때만 VAS 네이티브 역할을 선택한다. TOML/Markdown 파일의 존재만으로 등록·실행을 단정하지 않는다.
- 이름 기반 선택 인자가 없으면 일반 하위 에이전트를 실제 생성한다. 아래 `[ROLE INSTRUCTIONS: 역할]` 본문 전체와 현재 요청·담당 파일·확정 토큰·완료 조건을 생성 요청에 넣는다. 인계 본문이 없고 VAS 저장소가 열려 있으면 `.agents/skills/<역할>/SKILL.md`를 읽어 전달한다. 역할 이름만 붙이고 지침을 생략하지 않는다.
- 위임 시 요청, 담당 파일, 확정 디자인 규칙, 완료 조건을 전달하고 반환 결과를 회수·검토한다. 호출 도구가 없으면 주 실행자가 순서대로 수행하며 별도 에이전트를 실행했다고 보고하지 않는다.
- 같은 파일을 여러 실행자가 동시에 수정하지 않는다. 검토자가 발견한 실패는 구현 담당자가 수정하고 관련 검증을 다시 실행한다.
- 대화 설정은 `.agents/SESSION.md`에 따라 에이전트 중 주 실행자만 저장한다. 사용자가 연결 화면에서 바꾼 설정도 있으므로 다음 요청·구현·위임·저장 전에 CLI로 최신 세션을 조회한다. 위임 시 확인한 설정과 세션 ID·revision을 함께 전달하고, 하위 에이전트는 설정 변경 제안만 반환한다. 오래된 revision 저장 충돌은 최신 설정과 비교한 뒤 처리한다. 화면의 저장 전 선택이나 샘플 보기만으로 디자인 범위를 확대하지 않는다.
- 검토자에게는 수정 금지를 명시하고 지원되는 경우 읽기 전용 권한을 부여한다. 일반 호출이 부모 권한을 상속하면 별도 샌드박스라고 보고하지 않는다. 검토 전후 파일 변경 여부를 확인한다.
- 실제 호출 식별자·완료 상태·반환 결과와 구현 검증 결과를 함께 확인한다. 모델의 성공 선언이나 역할 설정 파일 검사만으로 실행 검증을 통과시키지 않는다.
- 결과 취합 전 최신 세션과 대조한다. 변경된 설정에 대한 이전 결과는 새 인계 ID로 고쳐 붙이지 않고 영향 범위를 확인해 갱신·재검증한다. 원본 필수조건과 실제 검사 대상 버전에 결과를 연결하고, 자동검사 통과와 사용자 직접 확인을 별도로 보고한다.
- 실제 프로젝트의 테스트 명령을 확인해 실행하고 명령·종료 코드·결과를 보고한다. 실행하지 않은 검사는 통과로 표시하지 않는다.
- UI는 브라우저 캡처와 참고 화면을 비교해 수정한다. 도구가 없으면 미실행 사실과 남은 확인 항목을 보고한다.
- 위험한 변경만 필요한 승인을 확인하고 이미 승인된 범위는 계속 진행한다. 비밀값과 운영 데이터는 인계에 포함하지 않는다.
