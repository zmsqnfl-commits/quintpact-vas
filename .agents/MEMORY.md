# 프로젝트 기억 읽고 쓰기

프로젝트가 기억하는 것은 프로젝트 폴더의 `vas-state/` 한 곳에 있다. 폴더를 옮기거나 이름을 바꾸거나 다른 도구로 열어도 같이 따라온다. 전부 Markdown이라 도구 없이 읽고 고칠 수 있다.

```
vas-state/
  now.md      지금 상태 한 장. 시작할 때 항상 읽는다
  index.md    기록 목차. 한 줄에 한 건
  log/        작업 기록. 한 건에 파일 하나 (0012.md)
  refs/       사용자가 준 참고 자료
```

Python이 있으면 `python -B scripts/vas.py start`, `plan`, `done`, `recall`이 이 파일들을 읽고 쓴다. Python이 없으면 아래 양식대로 직접 읽고 쓴다. 어느 쪽으로 써도 같은 파일이다.

## 시작할 때

1. `vas-state/now.md`를 읽는다. 없으면 첫 대화다.
2. `vas-state/index.md`에서 지금 요청과 같은 파일·화면·기능을 다룬 줄을 고른다. 고른 기록만 연다. 한 번에 다섯 건을 넘기지 않는다.
3. 연 기록이 지금 파일과 맞는지 스스로 확인한다. 파일이 없어졌거나 내용이 달라졌으면 그 기록은 쓰지 않는다. 사용자에게 기억을 쓸지 묻지 않는다. `start`가 `changedSinceRecord`로 “기록 뒤에 바뀐 파일”을 알려 주면 그 기록의 `확인`은 예전 파일에 대한 것이다. 지금 결과로 쓰지 말고 그 파일에 걸린 확인만 다시 한다. 바뀌지 않은 파일의 확인까지 다시 할 필요는 없다.
4. 기억과 지금 요청이 다르면 지금 요청을 따르고 `now.md`를 고친다.
5. 기록의 `안 된 것`에 적힌 방법은 다시 시도하지 않는다. 같은 방법이 꼭 필요하면 무엇이 달라졌는지 먼저 확인한다.

## 지금 상태 (`now.md`)

```
# 지금 상태

판: 3 · 고친 날: 2026-11-16 · 고친 곳: claude

## 요청
사용자가 한 말. 바뀌면 바뀐 말로 고친다

## 대상
새 앱인지 기존 앱인지, 앱 폴더

## 완료조건
- [ ] C1 무엇이 되면 끝인지 (확인 방법)
- [x] C2 확인을 마친 조건

## 정해진 것
- 정한 것 (이유) — 사용자가 정했는지, 제안을 받아들였는지

## 열린 질문
## 다음 할 일
## 마지막 확인
```

- 고칠 때는 먼저 다시 읽는다. `판` 숫자가 읽었을 때와 다르면 다른 곳에서 고친 것이므로 그 내용에 합쳐서 쓴다. 쓰면서 `판`을 1 올린다.
- 바꿀 칸만 바꾸고 나머지 칸과 사용자가 만든 칸은 그대로 둔다.

## 기록 한 건 (`log/0012.md`)

작업을 마치거나 멈출 때 사용자가 시키지 않아도 한 건을 남긴다. 번호는 가장 큰 번호에 1을 더한다. 이미 있는 기록은 고치지 않고 새 기록을 더한다.

```
---
date: "2026-11-16"
title: "가격표 화면 추가"
summary: "카드 세 장으로 바꾸고 390px에서 확인"
by: "claude"
tags: ["화면", "가격표"]
files: ["src/price.html", "src/price.css"]
fingerprints: {"src/price.html": "9f2c41d07ab35e18"}
---

## 한 일
## 이유
## 확인
- 무엇을 어떻게 확인했는지 → 통과 | 실패 | 미실행
## 안 된 것
- 해 봤는데 안 된 방법과 안 된 이유
## 다음 할 일
```

- `확인`은 내가 직접 보고 적는 보고다. 사용자가 확인했거나 받아들였다는 뜻이 아니다. 사용자가 직접 보고 말해 준 것은 “사용자 확인: …”으로 따로 적는다.
- `tags`에는 화면이나 기능 이름을 한두 개 적는다. 나중에 관련 기록을 찾을 때 쓴다. `by`에는 쓰고 있는 도구 이름(claude, codex 등)을 적는다.
- `fingerprints`는 `done` 명령이 적는 줄이다. 기록할 때의 파일 모습을 짧은 값으로 남겨, 다음 `start`가 그 뒤에 파일이 바뀌었는지 알려 준다. 직접 쓸 때는 이 줄을 적지 않는다. 값을 지어내지 않는다. 이 줄이 없는 기록은 `start`가 “대조 안 함”으로 센다.

기록을 쓴 뒤 `index.md` 끝에 한 줄을 더하고 `now.md`의 `다음 할 일`과 `마지막 확인`을 고친다.

```
- 0012 | 2026-11-16 | 가격표 화면 추가 | 카드 세 장으로 바꾸고 390px에서 확인 | src/price.html, src/price.css | #화면 #가격표
```

## 적는 것과 적지 않는 것

- 적는다: 사용자가 정한 것과 이유, 완료조건, 바뀐 파일의 상대 경로, 확인한 방법과 결과, 안 된 방법.
- 적지 않는다: 비밀값, 개인정보, PC의 절대 경로, 명령 출력 원문, 추측.
- 확인하지 않은 것을 통과로 적지 않는다. 내가 제안한 것을 사용자가 정한 것처럼 적지 않는다.
- 디자인에서 정한 것은 앱의 `src/DESIGN.md`에 적는다. 여기(`now.md`의 정해진 것)에는 “디자인: <스타일 키 | 참고 | 알아서 위임> (사용자)” 한 줄만 남긴다.
