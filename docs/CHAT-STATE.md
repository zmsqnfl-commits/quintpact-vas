# 대화 설정 저장과 다시 시작하기

프로젝트 폴더의 VAS 시작 화면에서 저장한 [프로젝트 작업 지시](PROJECT-ROOT.md)는 앱 루트의 `VAS-PROJECT-PROMPT.json`을 사용합니다. 아래 PC 전용 세션과 별개이며, 세션 생성 전이나 세션 저장소 접근 실패 시에도 먼저 읽습니다. 세션에는 문구를 복제하지 않고 작업과 연결할 때 해시·판본을 대조합니다.

VAS 2.13.1의 대화 설정은 작업 폴더·요구사항·디자인 범위·완료조건·남은 질문을 다음 대화로 이어줍니다. 별도의 [최신 진행 요약](CHAT-PROGRESS.md)은 작업 단계·결정 이유·변경 파일·검사와 남은 문제를 이어줍니다. 같은 PC에서 같은 VAS 폴더를 열고 “이어서 해줘”라고 하면 AI가 전용 CLI로 조회합니다. Python 3.10+와 파일 실행 도구가 필요합니다. [로컬 디자인 화면](CHAT-DESIGN.md)에서도 같은 설정을 저장하며, 이 설정으로 [구현 인계를 준비하고 결과를 대조](CHAT-EXECUTION.md)합니다.

`finish`는 `vas-state/progress/`에도 정제한 최소 요약을 남깁니다. 같은 폴더를 여는 새 호스트가 `start`에서 “개인 세션 없음”과 이전 요약을 함께 볼 수 있습니다. 실제 검사와 현재 파일을 대조해 이어가며 개인 저장소·키·원본 대화는 함께 옮기지 않습니다. [프로젝트 진행 요약과 작은 수정](PROJECT-ROOT.md)

공유 요약은 단계·작업 요약·검사 이름과 상태·다음 행동을 담습니다. 준비한 작업에서 확인한 목표·완료조건·결정·미해결 항목도 함께 남깁니다. 같은 판본의 Markdown을 열면 CLI 없이 읽을 수 있고, 이전 기록에 Markdown이 없으면 원래 JSON을 그대로 보존합니다. 같은 폴더를 읽을 수 있는 사람도 볼 수 있으므로 비밀이나 개인 식별 정보는 넣지 마세요. 이 디렉터리는 Git과 VAS 배포에서 제외됩니다. 앱의 배포·백업·동기화 여부는 사용자가 결정합니다.

공유 저장은 이전 판본을 삭제하거나 덮어쓰지 않고 새 판본을 기록한 뒤 다시 읽습니다. 두 호스트가 동시에 쓰면 오래된 판본은 충돌로 표시됩니다. 최신 `start`의 요약을 대조한 뒤 해당 `sharedProgress.revision`을 사용하세요. 저장이 중간에 끊긴 데이터는 확인 표시가 생기기 전까지 읽지 않습니다. JSON은 판본당 32 KiB, 읽기용 Markdown은 64 KiB, 전체 기록은 2,048개 판본 슬롯까지 허용합니다. 파일 시스템이 배타적 새 파일 생성을 보장해야 합니다. 저장 한도에 닿으면 실패를 보고하고, 성공한 개인 체크포인트와 실패한 공유 저장은 구분합니다.

- 2.13.1부터 **새 공유 기록**을 처음 쓸 때 연결이 바이트 범위 잠금 미지원을 명시하면 새 파일 생성 방식으로 고정합니다. 모든 호스트가 같은 다음 판본을 놓고 한 번만 생성하므로, 같은 이전 판본에서 서로 다른 두 기록이 모두 성공할 수 없습니다. 완료 기록은 2.13.0 공유 기록 판독기와 호환되고, 이 형식에 추가 기록할 때는 2.13.1 이상이 필요합니다. 바이트 잠금이나 디렉터리 잠금을 지원하지 않는 연결에서도 2.13.1의 읽기 전용 시작은 고정한 폴더와 지시 판본을 재확인합니다. 프로젝트 지시 파일을 변경할 때는 원래 쓰기 잠금이 필요합니다.
- 작성 중인 판본을 두 번째 쓰기가 앞지를 수 없으면 `shared_progress_pending`을 반환합니다. `start`와 Windows 화면은 마지막으로 완료된 기록을 읽습니다. 이전 쓰기가 끝나길 기다리거나 원래 요약과 판본으로 재시도하세요. 온전히 기록된 같은 파일은 재사용하지만 불완전한 파일은 덮어쓰거나 건너뛰지 않습니다. 복구할 수 없으면 마지막 완료 기록을 보존하고 새 프로젝트 위치에서 이어가세요.
- 이미 바이트 잠금 방식으로 사용한 폴더에서 잠금 미지원 오류(`shared_progress_lock_unsupported`)가 나면 기존 방식을 유지합니다. 잠금을 지원하는 연결에서 최신 판본을 확인하고 다시 저장하세요. 일시적인 잠금 자원 부족(`shared_progress_lock_unavailable`)이나 다른 작성자와의 경합(`shared_progress_busy`)은 먼저 잠시 뒤 재시도하세요.


## 사용 흐름

1. VAS 폴더를 코딩 AI에서 열고 만들거나 수정할 앱을 설명합니다.
2. AI가 실제 작업 폴더와 조건을 정리하고 이 PC에 설정 요약을 저장한다고 알려줍니다.
3. 새 대화에서 “이어서 해줘”라고 하면 저장한 조건·질문·진행 요약을 읽고 실제 원본과 검사 상태를 확인해 이어갑니다.
4. 여러 작업이 있으면 한 번 선택합니다. 대상 폴더가 사라지거나 교체되면 실제 대상을 확인합니다.
5. “진행 요약만 지워줘”는 요약만, “저장한 설정 지워줘”는 설정·연결 정보·요약을 지웁니다. 앱 파일은 유지됩니다.

명확한 새 작업은 이전 작업의 설정을 자동으로 합치지 않습니다. 현재 요청이 저장 정보보다 우선합니다. 계획만 요청했고 실제 대상 폴더가 아직 없다면 폴더 생성과 지속 저장을 완료했다고 표시하지 않습니다. 저장을 원하지 않으면 “이번 대화에서는 저장하지 마”라고 말하세요. 진행 요약도 저장하지 않습니다.

## 저장하는 것과 하지 않는 것

| 항목 | 처리 |
|---|---|
| 작업 이름·요구사항·디자인 선택·완료조건·남은 질문·다음 행동 | 정제한 설정 요약 저장 |
| 마지막 단계·결정 이유·변경 상대 파일·검사와 미실행·남은 문제 | 설정과 별도인 최신 진행 요약 한 건 저장 |
| 실제 작업 폴더 경로·디렉터리 식별자 | 제품 밖의 PC 전용 연결 정보에 저장 |
| 원본 채팅·전체 코드·원시 도구 출력·누적 실행 이력 | 저장하지 않음 |
| 완료·테스트 통과·권한 승인 표시 | 저장 설정에서 실행 증거로 사용하지 않음 |
| 기존 작업 기억/RAG | 별도 동의·저장·삭제 체계 유지 |

참고용 미해결 질문은 `questions`, 구현 결정을 막는 핵심 미정은 선택 필드 `blockingQuestions`에 구분합니다. 차단 질문은 0~10개의 비어 있지 않은 문자열이며 남아 있으면 구현 인계 준비가 멈춥니다. 기존 설정에 이 필드가 없으면 종전대로 이어가고 참고 질문을 자동 차단하지 않습니다. 이미 답한 질문은 지우고 결정 내용을 요구사항에 반영합니다. `nextStep`은 다음에 실제로 할 행동이며 저장된 JSON·문구는 실행 명령이나 추가 권한이 아닙니다.

기본 위치는 Windows 사용자 로컬 데이터의 `VAS/chat-sessions/` 아래입니다. 제품 소스·ZIP·공개 사이트에 포함하지 않습니다. 경로를 뺀 설정 출력과 PC 전용 연결 정보를 구분합니다. 알려진 비밀값·연락처·경로 패턴을 정제하지만 모든 민감정보를 알아내는 보안 검사는 아닙니다. 비밀값을 설정에 넣지 마세요.

선택 기능인 작업 기억과 대화 설정 저장은 별개입니다. 2.13.1의 Windows 작업 기억은 별도 서버 동의가 있어야 기록하며, 과거 기록 파일이나 브라우저의 동의 값으로 자동 활성화하지 않습니다. 업그레이드 후 기억이 꺼져 있어도 대화 설정이 삭제된 것은 아닙니다. 기존 기억의 보존·용량 제한은 [운영 가이드](OPERATIONS.md)를 참고하세요.

## 실패와 변경 처리

- 두 대화나 연결한 화면이 동시에 같은 설정을 수정하면 저장 버전(revision)을 비교해 오래된 덮어쓰기를 거부합니다. AI가 최신 내용을 읽고 변경을 비교합니다. 저장 전 화면 편집은 충돌이 나도 남아 있으며, 사용자가 최신 불러오기를 선택하면 초안을 버리고 새 설정을 읽습니다.
- 손상된 파일이나 지원하지 않는 형식은 빈 상태로 덮어쓰지 않습니다. 저장 실패는 실패로 알리고 현재 대화에서 진행합니다.
- 진행 요약만 손상되면 `progress.status: invalid`로 본문을 숨기고 정상 설정은 계속 조회합니다. 자동 삭제·덮어쓰지 않습니다. `stale`이면 달라진 문맥을 실제 원본과 대조합니다. `available`도 설정 문맥 일치만 뜻하며 현재 파일·검사 통과를 보증하지 않습니다.
- 같은 설치를 업그레이드해 비밀값 정제 규칙이 강화되면, 형식이 정상인 이전 설정은 정제한 복사본으로 조회하고 `reviewFields`로 확인할 항목을 알립니다. 조회·내보내기·`prepare`는 저장 파일을 바꾸지 않으며 다른 정상 작업도 계속 사용할 수 있습니다. 해당 작업의 `prepare`는 `needs-input`과 `settings.review`를 반환합니다. AI가 정제된 요구사항을 확인하고 전체 설정을 `save`한 뒤에만 새 revision으로 구현을 준비합니다. 디자인 화면의 저장만으로 이 확인을 대신하지 않으며, 알려지지 않은 필드나 잘못된 타입·연결 정보는 계속 거부합니다.
- 폴더가 이동되면 사용자가 확인한 경로로 다시 연결합니다. 이름이 비슷한 다른 폴더를 자동 선택하지 않습니다.
- VAS 도구 자체를 이동하거나 다른 PC로 옮기면 이전 저장소가 자동 연결되지 않습니다.
- 새 버전을 다른 폴더에 압축 해제해도 이전 설치의 세션을 자동 가져오지 않습니다. 기존 설치와 사용자 데이터를 보관하세요. 공개 설정 출력만으로는 PC 전용 대상 연결을 복원할 수 없습니다.
- Python이나 쓰기 권한이 없으면 현재 대화로 설정을 정리합니다. 저장·복원이 됐다고 표시하지 않습니다.
- 제한된 Windows 호스트가 PC 전용 저장소를 읽지 못하면 저장소 접근 실패를 알립니다. 접근 권한을 자동으로 변경하거나 읽지 못한 설정을 복원했다고 주장하지 않습니다.

화면에서 저장해도 AI가 자동으로 깨어나거나 진행 중인 대화 문맥이 바뀌지는 않습니다. 다음 요청·구현·위임·저장 전에 AI가 CLI로 최신 설정을 읽습니다. 연결 화면은 약 4초마다 최신 설정을 확인하며 저장 전 편집이 없을 때 반영합니다. 저장만으로 앱이 구현되거나 검증된 것은 아닙니다. CLI 형식과 명령은 [에이전트 저장 절차](../.agents/SESSION.md)에 있습니다.

## 저장 설정을 실행에 연결하기

`prepare`는 선택한 세션 ID·revision·설정 해시·역할 자료 해시를 담은 인계를 만듭니다. 질문 두 목록과 다음 행동도 참고용 `context.conversation`으로 JSON·프롬프트에 전달합니다. 실제 대상 경로는 로컬 CLI 응답에서만 확인하며 공개 인계에 복사하지 않습니다. 작업 요청이나 필수 완료조건이 없거나 차단 질문이 남으면 `needs-input`으로 반환합니다.

이후 설정이나 역할 자료가 바뀌면 이전 인계의 결과를 그대로 사용할 수 없습니다. AI가 새 지시와 진행 중인 작업을 대조하고 영향을 받는 검사만 다시 합니다. `assess`는 결과를 현재 인계와 원래 조건에 대조할 뿐 앱을 실행하거나 테스트하지 않습니다. 두 명령은 설정·앱 파일·실행 이력을 저장하지 않으며 결과 평가도 세션의 완료 표시로 저장하지 않습니다. work가 있는 assess는 명시한 파일을 읽어 현재 지문도 대조합니다.

요구사항·질문·디자인 변경은 먼저 최신 설정 전체를 `save`합니다. 구현·검사·읽기 전용 평가 뒤에는 최신 `resume`을 읽고 `checkpoint`로 진행 요약과 실제 다음 행동을 함께 저장합니다. 남은 실패 수정, 미실행 검사, 후속 요청 대기처럼 실제 상태에 맞추며 사용자 직접 확인이 미실시라는 이유만으로 항상 수동 검사를 추가하지 않습니다. 의미 있는 작업 구간 끝에 저장하고 재조회합니다. 중단·오류 때도 확인한 범위만 남기고 저장 실패는 미저장으로 알립니다.

진행 요약은 최신 한 건의 에이전트 보고입니다. 별도 [실행 기록](CHAT-WORK.md)에 위임 반환과 선택 파일 지문을 연결하며, 주 실행자가 실제 도구의 반환을 확인합니다. 저장된 `passed`는 당시 보고입니다. `checkpoint`는 세션 revision도 올리므로 계속 작업할 때 새 revision으로 인계를 준비하며 이전 평가를 새 결과로 바꾸지 않습니다. PC 전용 진행 기록 원본은 웹 응답·공유 `export`·`prepare` 인계에 자동 포함되지 않습니다. 로컬 허브의 프로젝트 진행 요약은 별도로 저장한 최소 공유 요약을 읽습니다.
