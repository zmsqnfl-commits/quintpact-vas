# 따로 부탁하지 않아도 디자인 챙기기

프로젝트에는 `design-craft` 스킬이 기본으로 들어 있습니다. “재고 앱 만들어줘”처럼 기능만 말해도, 화면이 있는 작업이면 코딩 AI가 디자인 계획을 먼저 세우고 완성한 화면을 스스로 검수합니다. 별도 설치나 계정은 필요하지 않습니다.

## 사용자는 무엇을 하면 되나

평소처럼 요청하면 됩니다. 디자인이 정해지지 않은 새 화면이면 AI가 만들기 전에 한 번 묻습니다. 셋 중 편한 방법으로 답하세요.

- 원하는 느낌·색을 말하거나 참고 사이트·이미지를 준다.
- AI가 보여 주는 스타일 중 번호로 고른다. 28개 전체는 `ui/style-preview.html`을 더블클릭하면 타일로 볼 수 있습니다(서버가 필요 없습니다). 번호와 설명은 [스타일 목록](STYLES.md)에도 있습니다.
- “알아서 해줘”라고 한다. AI가 주제에 맞게 정해 두세 줄로 알린 뒤 진행합니다.

마음에 들지 않으면 그때 바꾸라고 하면 됩니다.

한 번 정한 디자인은 앱 폴더의 `DESIGN.md`에 남습니다. 스타일을 골랐으면 그 키와 색·여백·글꼴이 적히고, 그 스타일의 글꼴 파일과 라이선스가 앱의 `src/assets/fonts/`로 복사됩니다. 다음 대화에서 AI가 이 파일을 읽고 같은 디자인을 이어가므로 같은 것을 다시 고를 필요가 없습니다. 직접 열어 고쳐도 됩니다.

## AI가 따르는 순서

| 순서 | 하는 일 |
| --- | --- |
| 정해진 것 확인 | 사용자의 말, 저장한 프로젝트 지시, 확정 토큰, `DESIGN.md`를 먼저 따릅니다. 정해진 것은 다시 묻지 않습니다. 아무것도 정해지지 않은 새 화면이면 원하는 디자인이나 참고할 사이트·이미지가 있는지 한 번만 묻고, 없으면 AI가 정합니다 |
| 계획 | 화면의 가장 중요한 한 가지 일, 색 4~6개, 글꼴, 넓은 화면과 좁은 화면의 배치, 기억될 한 가지를 적습니다 |
| 구도 | 실제 내용으로 뼈대를 만들어 넓은 화면과 좁은 화면에서 봅니다. 구도가 틀리면 꾸미기 전에 고칩니다 |
| 적용 | 계획의 색·글꼴만 씁니다. 문구와 한글 줄바꿈, 버튼·입력 상태와 빈 화면을 챙깁니다 |
| 스스로 검수 | 완성한 실제 화면에서 가장 약한 세 곳을 찾아 고칩니다. 잘림·겹침·오탈자·끝줄에 한두 글자만 남는 줄바꿈은 보내기 전에 고칩니다 |
| 기록 | 실제 결과에 맞게 `DESIGN.md`를 고치고, 화면 검수 결과를 작업 기록에 남깁니다 |

기존 디자인을 유지하는 작업에는 새 스타일을 만들지 않습니다. 고친 부분의 화면 검수만 합니다. 화면이 없는 작업에는 적용하지 않습니다.

## 다른 디자인 기능과의 관계

- 참고 이미지가 있으면 [디자인 분석 스킬](DESIGN-ANALYSIS.md)이 실제 원본을 다섯 요소로 분석하고, 그 결과가 계획의 출발점이 됩니다.
- 디자인 스튜디오에서 고른 스타일과 확정 토큰이 있으면 그것이 우선입니다. [샘플 참고 범위](DESIGN-REFERENCE-SCOPE.md)대로 샘플의 기능은 따라 만들지 않습니다.
- 기능과 변경 범위는 사용자의 요청과 완료조건이 정합니다. 이 스킬은 기능을 추가하거나 범위를 넓히지 않습니다.

## 기본 탑재 경로

- 정본은 `.agents/skills/design-craft/`이고 Claude용 사본은 `.claude/skills/design-craft/`입니다. 글꼴, 화면 문구, 한국어 화면, 검수표, 기록 양식은 `references/`에 있으며 필요할 때만 읽습니다.
- 루트 시작 지침(`AGENTS.md`, `CLAUDE.md` 등)이 화면 작업에 이 스킬을 연결합니다. 호스트의 자동 스킬 탐색에만 기대지 않습니다.
- 인계 프롬프트의 작업 순서와 역할 지침에도 같은 순서가 짧게 들어 있어, 다른 앱 폴더에서 작업할 때도 적용됩니다.
- 네이티브 Designer 지침은 스킬 본문을 함께 포함합니다. 실제 역할 호출 가능 여부는 코딩 호스트에 따릅니다.

## 한계

스킬이 들어 있다는 것과 화면이 실제로 검수됐다는 것은 다릅니다. 코딩 AI가 화면을 열 수 없는 환경이면 시각 검수는 미실행으로 보고됩니다. 브라우저 폭 조절은 실제 휴대전화 확인과 다르고, 이 스킬이 모든 앱의 디자인 품질을 보증하지는 않습니다. 기능 검사 통과와 화면 검수 결과는 따로 보고됩니다.
