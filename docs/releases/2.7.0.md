# VAS 2.7.0

**Released September 7, 2026**

VAS 2.7.0 expands the design studio with distinct visual collections, interactive sample websites, and a complete application built through the VAS handoff process. It also improves how design choices and role instructions reach the coding agent, with recorded implementation, review, and browser verification.

VAS helps you turn a project request and a chosen design direction into a prompt for your coding tool. The workflow is: describe the work, choose and refine a style, copy the generated prompt, and let the coding agent inspect the actual project before making changes.

## 3. More complete design handoffs

VAS now preserves the project requirements, reference URLs, selected preset, confirmed design tokens, and full role instructions more consistently across browser and Python handoff paths.

This release fixes cases where long instructions were truncated, design token data was incorrectly removed during sanitization, or a small manual edit caused the original preset association to be lost.

The coding agent receives concrete guidance about layout, typography, spacing, responsive behavior, interaction states, and the chosen visual profile. The sample's fictional content is a visual reference; it is not treated as your project's real business data.

Copying the prompt remains the default handoff action. Saving `VAS-AI-HANDOFF.json` is optional. For an existing project, the coding agent must read the actual source files and preserve that project's technology stack.

## 4. Agent execution backed by actual runs

The workflow distinguishes between a host that supports registered VAS roles and a host that can only create general subagents.

When general subagents are used, VAS instructions require the complete role text, task scope, assigned files, confirmed design rules, and completion criteria to be passed into the call. The main agent then collects the results, reviews the evidence, routes issues back for correction, and repeats the affected checks.

The recorded validation includes actual designer, implementer, and reviewer calls. Reviewer instructions prohibit source edits, and file hashes were compared before and after review. Inherited host permissions are not presented as a separate security sandbox.

Validation commands now propagate real failure codes. On Windows, the verification wrapper can reuse an existing mapped drive when npm cannot run directly from a UNC working directory.

## 5. Morrow: a working application built through VAS

The release includes **Morrow**, a creative task board using the Bento Studio design, at `src/proof-app/index.html`.

Morrow was built from a real five-step VAS project form, an exported handoff, a generated design concept, implementation by a separate agent, and independent review.

It supports:

- Creating and editing a task title, notes, category, status, and optional due date.
- Marking tasks complete and combining text search with category and status filters.
- Archiving and restoring tasks, deleting tasks, and undoing the most recent deletion.
- Saving data in the browser and exporting the current records as JSON.
- Clearly labeled example tasks, empty states, input validation, and persistent storage-error guidance.
- Keyboard operation and responsive layouts at 1440, 768, 390, and 320 pixels.

Verification found and corrected a dialog focus-cycling issue, small mobile completion targets, and a mismatch that allowed more than 5,000 tasks to be saved but rejected them on reload. A browser regression check now creates a 5,001st task and confirms that all 5,001 records remain readable after reloading.

Morrow is a browser-local application. It does not include accounts, a backend, an AI API connection, JSON import, or synchronization between devices.

The request, original handoff, design specification, and execution results are recorded in `docs/verification/`. The original handoff was generated during development on VAS 2.6.4 and is preserved with its original version and integrity hash.

## 7. Downloads and getting started

| File | Purpose |
| --- | --- |
| `VAS-2.7.0-windows.zip` | Complete Windows distribution with the local launcher, design studio, handoff tools, sample sites, and Morrow |
| `VAS-Client-Form-2.7.0.zip` | Standalone project request form for sharing |
| `release-manifest.json` | Release version, source commit, artifact sizes, and hashes |
| `SHA256SUMS.txt` | SHA-256 checksums for the two ZIP downloads |

For the complete Windows version:

1. Download `VAS-2.7.0-windows.zip`.
2. Extract the entire archive into a new folder.
3. Run `Run-VAS-System.bat` on Windows 10 or 11 with PowerShell 5.1 or later.
4. Choose a new project or an existing project, describe the work, and select a design.
5. Open the actual project folder in your coding tool and paste the generated prompt.

Keep the previous installation folder and any user data when upgrading. The application version is now 2.7.0; the handoff v3 and result v1 formats and existing design storage keys remain compatible. Updating the version does not intentionally reset saved settings.

Existing project paths belong only in the copied prompt, not in the exported JSON or work-memory records. Work memory remains opt-in. VAS does not run the existing target project as part of preparing its handoff.
