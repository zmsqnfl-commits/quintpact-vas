# VAS 2.13.0 — Start the right task and verify what the next agent inherits

Open the whole project in your coding host and say **“폴더 전체 색인해줘”**. The first three lines of the root agent instructions identify the application directory, the read-only start command and the first decision to clarify. [Windows project ZIP](https://github.com/zmsqnfl-commits/quintpact-vas/releases/download/v2.13.0/VAS-2.13.0-windows.zip) · [GitHub source ZIP](https://github.com/zmsqnfl-commits/quintpact-vas/archive/refs/tags/v2.13.0.zip)

### What happens at the first prompt

`python -B scripts/vas.py start` reads the application state, portable project prompt and this folder’s private session. A new folder with no session is a normal outcome. The coding agent chooses its next action using both this state and the current request. A storage error remains visible to the agent.

If a user mentions a previous menu board while indexing a fresh folder, the next question is whether to build a new board or bring over the existing one. If the user has already requested a migration, the agent clarifies its scope and acceptance criteria. Indexing does not trigger a transfer. Once the user identifies the old application, `python -B scripts/vas.py import --from "old app source"` previews eligible code. For an explicit transfer, pass the exact `--apply --expected-plan DIGEST` arguments returned by the preview. VAS checks that the plan still matches before copying eligible files into `src/` and leaves existing files in place. Credentials, operational data and NAS deployment are handled separately. An optional Claude Code session hook can invoke the same read-only command when the host supports project hooks. [Project guide](https://github.com/zmsqnfl-commits/quintpact-vas/blob/v2.13.0/docs/PROJECT-ROOT.md) · [Optional hook](https://github.com/zmsqnfl-commits/quintpact-vas/blob/v2.13.0/docs/CLAUDE-START-HOOK.md)

### From agreement to the next conversation

For a confirmed, isolated text or style change, the agent can run `start`, edit, check and record the actual result with `finish --summary … --check …` without creating a session. For larger changes, data migration or deployment, the main agent saves the agreed task and completion conditions, reads the settings back and prepares the handoff before editing. At the end, `python -B scripts/vas.py finish` accepts the actual result report and progress summary, checks them against the prepared task, stores the checkpoint and reads the saved next action back. A paused or blocked segment can be recorded without a result report. The response separates what was checked, what remains and whether the checkpoint was confirmed. Both forms leave a small sanitized project summary under `vas-state/progress/`. A different host with access to that working folder can recover the summary while its own private session remains empty. The authenticated local Windows hub can display the shared checks and next action without opening another host’s private session.

### Read a handoff without the CLI

A new saved revision contains JSON and a readable Markdown view such as `vas-state/progress/000001.md`. Both describe the same committed record. A prepared task includes its agreed objective and completion criteria. A small edit retains any previously agreed scope. Recorded decisions, remaining work and actual checks are shown when available. Earlier JSON-only revisions remain readable.

If the CLI is unavailable, open the Markdown matching the latest numbered `.ok` marker and compare it with the current app. The local Windows hub also displays recorded details and the relative Markdown path. The agent creates the view during `finish`. The user can continue with a project’s own specification when requested. Editing the shared Markdown does not update the work agreement. This release provides a progress view rather than a four-document specification editor.

The application and its dependency files remain in `src/`. VAS settings screens, workflow commands and tests live in the visible tool directories. The private root development package is named `vas-tools` and its description identifies `src/` as the application. The named Windows ZIP, repository clone and GitHub source archive use the same project layout. The standalone form and external application handoffs retain their own entry points, project rules and portable role instructions.
