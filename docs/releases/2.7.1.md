# VAS 2.7.1

**Released September 8, 2026**

VAS 2.7.1 fixes three privacy issues and one Windows font-loading issue found after the 2.7.0 release. It retains the design collections, interactive sample sites, Morrow app, and handoff v3/result v1 formats introduced or supported by 2.7.0.

## What changed

### Downloaded handoffs now match the privacy boundary

An existing-project preview could remove sensitive text while the subsequent JSON download restored the raw request during design synchronization. The browser now sanitizes the complete document at finalization and again immediately before saving. Both download callers wait for that operation to complete.

Passwords, contact details, and recognized private absolute paths are removed from the downloaded payload. The selected project folder remains available in the copied prompt, where the coding agent needs it, and is excluded from the JSON. Provider selection is applied before the integrity hash is calculated.

### JSON credentials are covered across browser and Python paths

Credential filtering now handles quoted keys, nested objects and arrays, short passwords, escaped values, encoded JSON strings, duplicate keys, and common credential aliases. Browser generation and Python compatibility paths apply this policy before finalization. The optional reviewed-source ZIP path refuses files containing these credentials instead of exporting their original contents.

Legitimate design tokens, public reference URLs, and complete design guidance remain supported. Filtering is a safeguard for recognized formats; it cannot identify every possible secret hidden in arbitrary prose or an unknown encoding.

### Explicit memory deletion removes retained application copies

Deleting an individual record, clearing all records, or replacing imported memory now also removes previous-store, corrupt-recovery, and abandoned temporary copies managed by VAS. These operations run under the existing memory lock and do not create a new backup containing the removed records.

Surviving records and the pause setting are preserved for a valid store. Unrelated files are left alone. Normal writes retain their recovery backup behavior. Failed cleanup is reported as an error instead of a successful deletion.

This applies to VAS-managed local files. It does not erase earlier user exports, operating-system backups, NAS snapshots, or copies shared elsewhere. After upgrading, explicitly delete the affected records or clear memory to remove retained VAS copies.

### Bundled TrueType fonts load on Windows

The local Windows server now serves `.ttf` assets with `font/ttf`, restoring bundled fonts used by the design previews and Morrow. Binary fonts remain excluded from the text-reading API. No external font service or CDN was added.

## Verification

The regression cases use synthetic credentials and isolated temporary memory stores. They check real browser downloads, independent payload hash calculation, Python compatibility exports, source ZIP refusal, Windows memory API deletion, and actual HTTP font delivery.

Local verification passed **140 Python checks** (one Windows symlink permission skip), **77 browser scenarios**, **7 package checks**, and an extracted Windows runtime smoke test. Actual desktop/mobile Chrome rendering confirmed the bundled font loaded without overflow or page errors.

See the [four-issue verification record](../verification/privacy-font-fixes-2026-09-08.md) for commands, results, preserved behavior, and validation limits. Windows CI now includes these privacy and font regressions.

## Upgrade

Download `VAS-2.7.1-windows.zip` and extract the complete archive into a new folder. Close the older VAS instance and launch `Run-VAS-System.bat` from the new package. Existing user data and design storage keys are retained; no format migration is required.

The standalone request form is `VAS-Client-Form-2.7.1.zip`. Release assets include `SHA256SUMS.txt` and `release-manifest.json`. Previously published 2.7.0 artifacts remain available as historical releases.

Handoff files downloaded before this patch are not rewritten automatically. Regenerate them with 2.7.1 before sharing; if an earlier shared file contained a real credential, revoke or rotate that credential.
