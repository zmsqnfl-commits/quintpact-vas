# VAS 2.8.0 — Explicit scope and evidence-based completion

VAS 2.8.0 connects the task brief, design permissions and completion conditions while separating an AI's report from what has actually been checked. The everyday workflow remains simple: prepare the request, copy the prompt, and work in your coding host.

## Keep existing designs under control

Existing-project requests default to **preserve the existing design**. Necessary controls and accessibility adjustments reuse the current components and visual rules. A selected preset remains saved but is excluded from the active handoff in preserve mode. Partial changes name the permitted screens, elements and properties; a redesign never implies permission to delete data or change unrelated functions.

The selected scope reaches the preview, copied prompt and JSON together. Existing handoffs with no scope retain their original meaning instead of being silently rewritten with the new default.

## Define what a successful task means

New and existing requests can include up to 20 completion conditions. Each condition records its description, required/optional status and verification method: automated testing, manual observation or static review. Conditions also appear in the compatible string-based acceptance criteria so coding hosts receive the same instructions.

Generic guidance is kept separate from task-specific conditions. Empty conditions do not mean verified completion. Overlength inputs are rejected explicitly; when sensitive-data cleanup changes the request or conditions, the user reviews the sanitized final content before exporting it.

## Separate reports, assessment and acceptance

The compatibility result-import module now distinguishes **agent-reported status**, **VAS assessment**, and **user acceptance**. Moving a result to the next iteration or accepting a known limitation does not turn an unverified or failed check into a pass.

Missing evidence or self-reports remain **needs verification**. Blockers, failed checks and reported scope violations remain **incomplete**. Completion requires the original required conditions to be confirmed for the stated artifact version. Documentation and visual work can use direct manual or static review; automated tests are not mandatory for every task.

User observations live in a separate local review store and are bound to the exact result content and artifact version. Imported JSON cannot promote its own verified flags, observer names or attached evidence into trusted user observations. Incompatible artifact evidence is surfaced for correction. These local observations record user review; they do not provide cryptographic proof of an external AI's execution.

Result collection remains a compatibility feature, hidden from the default handoff flow. Direct CI/host collection and signing infrastructure are outside this release.

## Reject malformed data without hiding failures

Browser and Python validators now agree on numeric schema versions and iteration values, object/array shapes, item limits and machine-readable error codes. A 51st failed test or blocker cannot be silently cut away. Empty blocker records are rejected instead of disappearing. Historical coercible values can be repaired only through an explicit conversion review; normal validation stays strict.

The original reported status is retained separately from legacy status normalization. New evidence fields remain agent-submitted, and imported assessment/trust fields cannot grant completion.

## Give confirmation flags precise meanings

Automatic redaction, actual user confirmation and independent security verification are distinct facts. Input presence is not user approval, and a matching handoff hash means content linkage rather than execution or security verification. Existing credential-cleaning and local-data boundaries remain in place.

## Verification and upgrade

The release gates cover Python, real-browser workflows, package integrity, extracted Windows execution and source/package boundaries. Shared synthetic fixtures compare JavaScript and Python decisions; browser regressions exercise preserve/partial scopes, input review, direct observation, storage failures, stale results and forged imported trust. Exact gate results are recorded in [GitHub Actions](https://github.com/zmsqnfl-commits/quintpact-vas/actions) and the release workflow before publication.

Local release checks: **454 Python cases passed**, with one directory-symlink case skipped because this Windows account cannot create directory symlinks; **128 browser cases passed**. Windows runtime checks (14), runtime source checks (4), packaging checks (7), extracted-package execution (1) and release-boundary checks (4) also passed. Desktop and mobile screens were visually reviewed. GitHub repeats its Linux and Windows gates before publishing.

The handoff v3 and result v1 formats remain supported. New scope restrictions are included in existing prompt/acceptance fields, while new assessment information is kept separate. Close older VAS windows, extract the full Windows ZIP, and run `Run-VAS-System.bat`. Keep the existing `VAS-source` folder name and preserve user data. The ten-run stress suite is optional and was not requested for this update.
