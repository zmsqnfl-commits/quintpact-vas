# VAS 2.13.1 — Import an application from a connected project folder

Open the entire project directory in your coding host. The right directory contains `Run-VAS-System.bat`, the root agent guide, `scripts/`, and the application's `src/`. If the connected directory only contains Claude settings or agent definitions, reselect its parent.

## Review and transfer an app

A remote host may mount an explicitly selected source under a directory called `sessions`, `data`, or `backup`. This release checks the selected source, its contents, and protected path boundaries without rejecting an application just because its mount uses one of those names.

The preview lists eligible files and explains exclusions by relative path and category. Environment-variable lookups and blank password input handlers can move with the source code. Real credential literals, live operational settings, caches, and links are excluded. Common launchers, Markdown or text instructions, validated font and image formats, and example configuration can accompany the app. Binary assets have a separate bounded file size and still count toward the overall import limit.

1. Run `python -B scripts/vas.py import --from "path to old src"` and review both lists.
2. When the preview identifies an ambiguous file, inspect it locally. To request its inclusion, run a new preview with `--include "relative/file"`. Known secrets and live settings have a separate provisioning path.
3. Apply only the reviewed selection, using the original preview arguments and the exact `--apply --expected-plan DIGEST` arguments it returns. Any change to a reviewed input requires a fresh preview.
4. Start the imported app using its own entry point and check each required screen or service. A successful file copy is separate from application verification. Record the checks you actually ran with `vas.py finish`.

## Progress on mounted folders

New journals detect whether the filesystem supports the byte-range lock used by VAS. When locking is explicitly unsupported, a new journal uses exclusive creation and a fixed successor revision. A stale writer cannot skip an unfinished revision to publish a conflicting update. An existing byte-lock journal still requires a lock-capable connection.
