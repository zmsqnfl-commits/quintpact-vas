# VAS 2.8.1 — Reliable recovery and current handoffs

VAS 2.8.1 improves the everyday setup flow: preserve a recoverable draft, validate task conditions before declaring the handoff ready, clear outdated previews, and include a version-labelled visual reference alongside the confirmed design tokens. This is a handoff-quality update; it does not guarantee that an external coding AI executes or completes the development task.

## Preserve drafts until the recovery choice

Opening a form with an existing draft no longer permits background saves to replace it before the user chooses how to continue. Input, scheduled saves and page-exit saves share the recovery guard. A failed deletion preserves the draft and the recovery choice instead of starting a new save.

## Validate conditions before READY

An empty condition list remains optional. A condition row that has been added must contain text, cannot contain whitespace alone, and must stay within the 500-character limit. Browser and final policy checks use the same rules; inputs are not silently truncated. Errors identify and focus the relevant row, preserve the entered work and allow a retry. The new-project flow enters READY only after handoff preparation succeeds. A restored invalid condition also returns the user to its editable row.

**READY means the handoff materials are prepared. It does not mean the development task is complete or its checks have passed.** Existing completion-assessment rules remain strict.

## Keep the displayed prompt current

Changing the existing-project request, folder, design settings, provider or completion conditions clears the old preview and ready state. Use **Prepare handoff again**, copy or save to regenerate the current instructions. Generation results are tied to the input revision so an older asynchronous result cannot replace a newer request.

The preview, copied prompt and JSON agree on their shared requirements, design scope and conditions. The local folder location remains a prompt-only instruction and is excluded from JSON.

## Carry a usable visual reference

Active designs include a base-style reference, the confirmed tokens and the permitted application scope. The handoff identifies the VAS version and the release-tagged GitHub sample source separately from the runnable sample on the latest GitHub Pages deployment. The live sample is not claimed to match that release, and a cache query is not treated as an immutable snapshot. Release-tag links become available after the corresponding tag is published.

A custom selection keeps its base preset separate from user overrides: the sample illustrates the base style, while confirmed tokens govern the changed values. Sample text, photographs and business data are examples rather than requirements. Unknown styles receive no invented sample link. Every generated visual-reference record starts **unverified**; passing a URL does not mean that the coding AI opened it. An unavailable or unmatched reference must be reported as unverified.

Preserve-design mode excludes active styling instructions, tokens and sample references. Font-family tokens remain supported; a font name does not mean that its file has been supplied. Local assets and their usage terms must be checked in the tagged source. External CDNs and remote fonts remain prohibited. Automated screenshots, asset bundles and complete license-list generation are outside this patch.

## Upgrade and verification

The first-use guide now covers design preservation, partial changes, task conditions, draft recovery and the meaning of READY. The version checker includes that guide, and the standalone form includes the design-reference module.

Local verification completed on October 2, 2026:

- Python pytest: **476 passed, 1 skipped**. The skipped directory-symlink case requires a Windows permission unavailable to this account; it is not counted as a pass.
- Additional form, HTML, integrity and personalization checks: **11, 5, 27 and 9 passed**, respectively.
- Windows runtime and runtime-source checks: **14 and 4 passed**.
- Focused browser regressions: **8 draft-recovery cases**, **25 input/readiness and preview cases**, and **5 visual-reference cases passed**. These counts are not added again to the full-suite total.
- Final complete browser suite: **166 passed**, exit code **0**, approximately **2.1 minutes**. Two outdated assertions from the initial run were adjusted to the new preparation policy and visible error state, then the complete suite was rerun.
- Packaging, extracted Windows execution and release-boundary checks: **7, 1 and 4 passed**.

These are local verification results. Release packages are rebuilt from committed source so their manifests identify the release commit. Public ZIPs, manifests and checksums are checked by downloading and comparing them separately. Published CI, Pages and Release runs can be reviewed in [GitHub Actions](https://github.com/zmsqnfl-commits/quintpact-vas/actions). Regression checks use synthetic requests and temporary storage; previous release results are not reused as evidence for this patch.

The automated release workflow verifies Windows first: privacy regressions, the real server, integrated browser workflows and execution of an extracted Windows package. Only after that job succeeds does Linux verify the tag/version and main-branch relationship, run Python and the complete browser suite, and build and check the release packages. Assets and these release notes are published only when both jobs pass. Local tests remain distinct from confirmation of the publicly deployed Pages and downloaded archives; use the records linked above for that evidence.

The handoff v3 and result v1 formats remain supported. Extract the complete ZIP into a new folder and run `Run-VAS-System.bat`. Keep the stable `VAS-source` folder name and preserve existing user data. The optional ten-run stress suite was not requested and **was not run** for this update. Direct CI/host evidence collection and end-to-end execution by an external coding AI remain outside the verified scope.
