# VAS 2.7.2 — Connected workflow and privacy fixes

VAS 2.7.2 aligns the setup screens, design memory, generated instructions, compatibility tools, and operating documentation. The handoff v3 and result v1 formats remain compatible.

## What changes for users

- **Storage errors stay visible.** A failed persistent write, delete, import, pause, or consent change no longer switches silently to an empty temporary store. IndexedDB writes finish only after their transaction commits. A failed Windows history deletion reports failure, retains the live records, and can be retried.
- **Reset reaches the whole design flow.** Reset updates the current theme, URL state, open tabs, recommendations, and subsequent handoff downloads. Reloading no longer restores the design that was just reset.
- **Recommendations use confirmed designs.** Browsing presets and completing form questions do not create design preferences. Copying or saving a handoff, or confirming a design in the studio, records the chosen design when memory is enabled. Search events and older preview events without a confirmation marker are excluded from recommendations; their records are retained.
- **The handoff carries the user's constraints.** Long additional requirements remain in both the JSON and copied prompt. The file picker exports an attachment count and separate-attachment instructions; selected file names stay on screen.

## Privacy boundaries

The shared browser/Python redactor covers quoted and nested JSON, database credentials and driver/TLS URLs, AWS credentials, authorization headers, JWTs, complete private-key blocks, and YAML block scalars. Synthetic fixtures check both disclosure prevention and ordinary design/requirement controls. Ambiguous credential objects embedded in free text are withheld as a whole string.

The authenticated legacy project ZIP export sanitizes staged JSON before packaging. Missing Python, invalid JSON, unsafe files, or a sanitization failure stop that export. Original recovery backups and managed project copies retain source data and are not sharing artifacts.

Previously generated project knowledge indexes may contain partially filtered text. Only schema 2 indexes can enter search and handoff outputs; older indexes require explicit regeneration with the compatibility tool. VAS does not automatically inspect existing user projects to rebuild them.

## Integration and documentation

The optional result-import library clears stale results after invalid input, rechecks duplicates at acceptance, and requests fresh manual confirmation if its receipt disappears. Python and browser result contracts agree on integer iteration values. This library remains outside the default UI.

Operating documentation now distinguishes prompt generation from the coding host's source inspection, optional JSON from required steps, and host-specific agent registration from instruction files. Archived release/verification notes no longer appear as current operating instructions in document search.

## Validation

Validation on Windows completed with **210 passing Python checks and one symlink-permission skip**, **88 passing browser scenarios**, **7 passing package checks**, and **1 passing extracted Windows runtime scenario**. Four release-boundary checks and source-hash verification also passed. The credential suite contains 40 shared synthetic cases.

Connected browser scenarios use isolated synthetic state, including a real locked history file and 1440/390-pixel screens. No actual user project or memory contents are used. CI now runs these connected browser scenarios on Windows as well as the existing Linux browser suite.

The repository-wide source assessment reviewed 204 of 279 scoped files in full. Historical/passive resources account for the remaining coverage limit. This is evidence for the exercised boundaries, not a guarantee that arbitrary secrets are detectable or that every coding host executes agents identically. A handoff hash proves input consistency, not execution or test success. The optional ten-repeat stress suite was not requested.

## Upgrade

Use the updated Windows ZIP or update the existing source folder. Keep the stable `VAS-source` working-folder name; versions belong on release artifacts. Existing design selections remain until explicitly reset. Current form drafts are separate from opt-in work memory: new forms use browser localStorage, existing-form inputs use the tab's history state, and copying a prompt alone does not erase a draft.
