# VAS 2.15.1 — Old checks are not reused for a changed file

## Files are compared with their last record

2.10.0 taught the session flow to notice when a file changed after it was checked. The short start → plan → done flow introduced in 2.14.0 did not carry that over: a record said “passed”, and nothing told the next conversation that the file had since changed. This release restores that one property in the short flow.

- `python -B scripts/vas.py done … --file src/app.js` now stores a short fingerprint of each named file in the record, as one extra line in its header: `fingerprints: {"src/app.js": "9f2c41d07ab35e18"}`. It is the first 16 hex digits of a SHA-256 of the file with line endings evened out, so the same file checked out on another system reads as unchanged. No path outside the project and no file content is stored.
- `python -B scripts/vas.py start` compares the files named by the recent records with the files as they are now. Changed or deleted files are listed in `memory.changedSinceRecord`, for example `src/app.js (기록 0003 뒤 바뀜)`, and the message tells the agent not to use that record’s checks as the current result and to repeat only the checks on those files. Unchanged files are not rechecked.
- The newest record that names a file is the one that counts.
- No command was added and the user is not asked anything.

Limits: only files named with `--file` are compared, up to 64 files and 4 MB per file. Links and anything outside the project folder get no fingerprint. A record written by hand on a host without Python has no fingerprint; `start` counts it in `memory.notCompared` and never reports it as unchanged. The agent is told not to invent the value.

The blocking-question gate and the follow-up classification of the session flow are not part of the short flow. They remain available for sessions made from the screen.

## A check is the agent’s report

The record format now states that the `확인` section is what the agent saw for itself, not the user’s confirmation or acceptance. Something the user looked at and reported is written separately as “사용자 확인: …”. The entry instructions carry the same sentence.

## Tags

In a real-host run of 2.15.0 the agent left the record’s tags empty, which removes the strongest signal `recall` uses. The `done` example in the entry instructions and in `start` now includes `--tag`, and the record format asks for one or two screen or feature names and for the tool’s own name in `by`.

## README correction

The collapsed design section of the README still said that fonts, artwork and preview screenshots were bundled. That was corrected on `main` after 2.15.0 was tagged; the 2.15.0 ZIP carries the old sentences.

## Verification

Linux: 1,602 Python tests passed with 144 skipped for Windows PowerShell, 178 browser tests passed with 6 skipped, and the package and release-boundary checks passed. Two new tests cover the comparison: an unchanged file, a file with different line endings, a changed file, a deleted file, a newer record taking over, a hand-written record, an oversized file and a link.

Not verified in this release: a real host acting on `changedSinceRecord`, a second conversation on a real host, Codex, and the items listed as unverified in 2.14.0 and 2.15.0.
