# VAS 2.16.1 — A smoother first conversation

2.16.1 comes from running the downloaded 2.16.0 ZIP the way a new user would: extract it, open the folder in Claude Code, say the first sentence from the guide, come back the next day.

## The VAS command no longer asks for approval in Claude Code

Every conversation starts with `python -B scripts/vas.py start`, and work is recorded with `plan` and `done`. In Claude Code each of those calls stopped for an approval prompt, and in a test where the prompt could not be answered, the agent skipped `start` and missed the note that a file had been changed after the last record.

The project now ships `.claude/settings.json`, which allows `scripts/vas.py` run by `python`, `python3` or `py` in the Bash tool and by `python` or `py` in the PowerShell tool (with either slash). Nothing else is pre-approved. Claude Code checks each part of a chained command on its own, so `python -B scripts/vas.py start; another-command` still asks about the second part; the test run showed this in its refusal messages. Claude Code applies a project's settings only after the folder is trusted, which it asks once when the folder is first opened; until then the prompts stay as before. A headless run on the PC confirmed that Claude Code reads all seven rules and holds them back for an untrusted folder.

## Criteria are ticked when they pass

The `done` example in the start guide and in the `start` output now includes `--criterion C1`, with the rule to list only the criteria that were actually checked and passed. Before this, agents recorded checks but left every box in `vas-state/now.md` empty.

`plan` numbers criteria C1, C2, … itself. When an agent had already written our own label (“C1 …”), the page showed “C1 C1 …”. A leading C label is now dropped before numbering. Anything else at the start, such as “A4 용지”, “H1 제목” or “3개 이상”, is kept as written.

## A shorter first-use guide

`00-처음-사용하기.txt` still described the older session flow (`finish`, `vas-state/progress/`, `.ok` files) in its first half and the project memory in its second. It is rewritten around what actually happens now: extract, open the folder, say “이 폴더를 프로젝트로 지정하고 색인해줘”, answer the one design question, and say “이어서 해줘” next time. It is about 60 lines instead of about 150.

## Verification

Run on the public 2.16.0 ZIP before these changes:

- Linux: `start` → `plan` → `done` → editing a file → `start` reports it in `changedSinceRecord` → `recall` finds the record. All eight `ui/*.html` pages open from the folder at 1440 and 390 px with no console errors, no network requests and no horizontal overflow; the style preview loads all six fonts.
- Windows (PC): the same command sequence, and the local server started with `-NoBrowser` answers the hub and `/health` with version 2.16.0.
- A real Claude Code conversation in a fresh folder answered the first sentence without changing any file. When `start` could not run, the agent read `vas-state/` directly and still summarised the work correctly, but it could not see that a file had been edited after the last record; this is what the settings file avoids. In the earlier A-28 test, a new conversation read `src/DESIGN.md` and did not ask about design again; the app it built rendered at 1440, 768, 390 and 320 px with the copied font loaded and stamps kept after reload.

The results for 2.16.1 itself are in the commit that publishes it.
