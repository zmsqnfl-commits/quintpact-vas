# VAS 2.7.6 — Safer handoffs and reliable recovery

This patch addresses one confirmed credential-disclosure finding and two connected recovery defects discovered while rechecking VAS 2.7.5. The normal workflow remains: choose whether to use work memory, describe the task, select a design, copy the full handoff, then implement and verify in your coding host.

## HTTP credentials stay out of shared handoffs

The canonical browser and Python cleaners now remove complete free-text authorization values regardless of authentication scheme. This includes opaque Token, Digest, Negotiate, custom schemes, proxy headers, quoted YAML header keys and folded header lines. URI authority user information, including valid apostrophes and other userinfo punctuation, is removed before other substitutions can hide or leave pieces of it.

The policy reaches new and existing project prompts, final JSON downloads, compatibility export staging and shared Python consumers. Browser and Windows work-memory filters also exclude credential-bearing URI values, including when old records are read or exported. Ordinary public URLs, design tokens and following requirement lines remain covered by regression tests.

Filtering uses known structural boundaries. Text on the same line as an authorization field, or indented as its continuation, can be withheld together. Put unrelated requirements on separate, unindented lines. URI user information is excluded even when it contains only a username; keep the ordinary repository/reference address in the brief and configure authentication in the coding host.

## Failed imports preserve browser records

Built-in browser memory imports now commit an entire batch in one IndexedDB transaction. A quota error or transaction abort rolls back the batch instead of leaving partially updated records. Temporary in-memory storage prepares its replacement before applying it. Existing event identity aliases still merge without duplication across browser and Windows exports.

The file picker resets after success or failure, so the same file can be selected again. Windows memory retains its existing locked, atomic file-write path. Custom adapters remain responsible for the atomicity of their own `importData` implementation.

## Draft errors are visible and retryable

Draft auto-save, setting changes and deletion now check the storage operation result. A failed deletion leaves the recovery notice available for retry. Pending auto-save cannot hide an unresolved settings error. A successful JSON download is reported separately from a failed browser-draft cleanup; a cleanup failure no longer turns into a misleading overall success or download failure.

## Verification

Local pre-publication checks passed:

- Python: **340 passed, 1 permission skip**, followed by **1 passed, 0 skipped** in the narrowly scoped elevated Windows directory-symlink test; **341 checks verified in total**.
- Browser: **109 passed**, including actual final clipboard-handler output and JSON downloads, memory rollback/retry, mobile workflows and storage-error feedback.
- Package: **7 passed**; extracted Windows package workflow: **1 passed**; release/source boundaries: **4 passed**.
- Shared synthetic credential fixtures: **97 cases** across the affected browser, Python and Windows consumers. Normal public URLs, JSON boundaries, design tokens, requirements and handoff integrity remain checked.

One independent candidate review found two equivalent credential bypasses and a pending-auto-save feedback regression; all three were reproduced and corrected before final validation. The release workflow repeats its applicable checks before publishing assets. Exact commit and artifact SHA-256 values are included in the downloaded ZIP manifests, `release-manifest.json` and `SHA256SUMS.txt`.

The recheck covered 47 security-critical files and five connected surfaces, not an exhaustive manual audit of every repository resource. Tests use synthetic projects, records and credentials. Real user projects, memory and backups were not used as fixtures. The optional ten-run stress suite was not run. VAS handoff hashes establish content linkage; they do not attest that an external coding host executed instructions or passed its own tests.

## Upgrade

Close older VAS windows, extract the complete Windows ZIP, then run `Run-VAS-System.bat`. Keep an existing `VAS-source` working-folder name without a version suffix. Do not replace real work memory or workspace data with test fixtures. Previously shared handoffs are not changed retroactively. All 2.7.0 design collections, interactive samples and the Morrow proof application remain available.
