# VAS 2.8.2 — Distribution cleanup

VAS 2.8.2 corrects the separation between the product distribution and its development handoff. Downloadable packages and the public site exclude internal task boards, development reports and current-context files. Development requests and results are maintained in the separate handoff repository.

The product retains the improvements introduced in 2.8.1: draft recovery protection, task-condition validation before READY, outdated-preview clearing, version-labelled visual references and the updated first-use guide. This patch does not add new setup steps or change the handoff v3 and result v1 contracts.

## Package boundaries

The release builder omits internal work records and rejects those filenames if they appear in another copied directory. The knowledge index also excludes their content before generating its JavaScript payload. Regression tests inject nested and differently cased files, then check the index, both downloadable ZIPs and the Pages payload. User documentation, license notices, sample sites and the agent instructions used by the product remain available.

Public documentation links to release notes and published workflow runs for verification. Internal task boards are maintained outside the product repository.

## Verification and upgrade

The release workflow verifies Windows runtime, browser integration and an extracted package first, then runs the Python, complete browser and package gates on Linux before publishing. Public archives are downloaded separately to verify their checksums and manifests. These checks are distinct from execution by an external coding AI.

Extract the complete Windows ZIP into a new folder and run `Run-VAS-System.bat`. Existing design selections and handoff formats remain compatible. READY still means that handoff materials are prepared, not that development has been completed.
