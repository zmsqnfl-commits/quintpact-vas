# VAS 2.12.1 — Open the whole folder and build your app in src

The repository clone, GitHub source archive and Windows starter now open as the same application project. In a clean download the top-level `src/` is reserved for your code and contains only `src/.gitkeep`. Put the new application’s code, assets, manifests and deployment files under `src/`. For example, install, run, test and build from the directory containing `src/package.json` or `src/compose.yaml`. Preserve existing app files in their established locations. VAS screens and examples live in `ui/`, commands in `scripts/` and workflow guides in `docs/`. [Source archive](https://github.com/zmsqnfl-commits/quintpact-vas/archive/refs/tags/v2.12.1.zip) · [Windows project ZIP](https://github.com/zmsqnfl-commits/quintpact-vas/releases/download/v2.12.1/VAS-2.12.1-windows.zip)

This is the first Windows release with the shared project layout. The 2.12.0 tag stopped in release validation before Windows assets were published. Version 2.12.1 restores the role instructions carried by copied prompts from the standalone form and by handoffs to an external application.

## Start a project

1. Extract the archive into a fresh directory or clone the repository. Rename the folder before creating its first saved session.
2. Open the directory containing `project-layout.json`, `AGENTS.md`, `CLAUDE.md` and `src/` in the coding host.
3. Say **“폴더 전체 색인해줘”** or “Index this project folder.” The agent should inspect the app, read the saved project prompt and check for an existing session. With an empty starter it asks about the intended users and first feature. With an existing app it identifies that app and asks what to change.
4. Describe the result you want and ask the agent to build it. Double-click `Run-VAS-System.bat` when you want to edit the shared prompt or use the optional settings screens. Launch and distribute the finished app using its own entry point and dependencies. [Project-folder guide](https://github.com/zmsqnfl-commits/quintpact-vas/blob/v2.12.1/docs/PROJECT-ROOT.md)

The final **Copy prompt** action now identifies the current VAS project even before its first saved instruction. Its prompt directs the agent to implement and test under `src/`, check the agreed session before editing and read back the saved checkpoint. When you select an external existing application, the copied instructions use its actual folder and preserve its file layout.

## Standalone and external applications

Paste the prompt into a coding host opened at the external application itself. The handoff carries role instructions and uses that application’s own entry point, dependencies and test commands. The standalone form works without installing VAS inside the target app. In the current VAS project, the prompt keeps new application deliverables under its top-level `src/`.

## What the agent records

Before editing, the main agent checks the current prompt revision and the session for this project. Once the task is agreed, it creates or updates the session, reads its settings back and prepares that revision. After implementation, it compares actual checks against the agreed conditions, saves its next action and reads the checkpoint back. If the private store is unavailable it identifies the failed step and carries the confirmed scope in the current conversation. Each host must follow the project instructions and have the tools to perform these steps. [Execution guide](https://github.com/zmsqnfl-commits/quintpact-vas/blob/v2.12.1/docs/CHAT-EXECUTION.md)

An existing app can join the workflow partway through development. Record what can be inspected today and which checks were actually rerun. Keep earlier reports distinct from new test results. Independent review or delegation is recorded only when it happened.

## Upgrading

Keep the original app and its data. Extract into a new folder and transfer application-owned code and configuration after checking for conflicts. The 2.11.x Windows starter already used its top-level `src/` for the app. The 2.11.x GitHub source ZIP used its top-level `src/` for VAS screens. The portable project prompt can move with the app. Private sessions, progress and target bindings depend on the original PC and installation path. [Migration guide](https://github.com/zmsqnfl-commits/quintpact-vas/blob/v2.12.1/docs/MIGRATION.md)
