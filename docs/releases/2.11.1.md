# VAS 2.11.1 — Set up your project in the coding chat

**Extract the Windows starter, open its project folder in your coding host, and ask it to index the folder.** The agent checks whether the folder contains a new or existing app, asks the next useful setup question and carries your answers into implementation and verification. [Download the Windows project ZIP](https://github.com/zmsqnfl-commits/quintpact-vas/releases/download/v2.11.1/VAS-2.11.1-windows.zip)

## Try it in Codex or Claude Code

1. Extract the entire `VAS-2.11.1-windows.zip` into a fresh folder. Rename it for your project before creating its first saved session.
2. Open the folder containing `src/`, `.vas/`, `AGENTS.md` and `CLAUDE.md` in Codex, or start Claude Code from that directory.
3. Send the following message. Equivalent wording also works in a host that follows the project instructions.

> 이 폴더를 프로젝트로 지정하고 색인해줘

In English, you can say “Use this folder as my project and index it.” The setup runs in the conversation. If you already know exactly what to build, describe that work directly.

Your application belongs in the root `src/` folder. VAS tools and guides live in `.vas/`. The named Windows ZIP provides this layout. GitHub's automatic source archives contain the VAS development repository. For an existing app, keep a backup and check its own files and instructions before transferring them into a fresh starter. [Project-folder guide](https://github.com/zmsqnfl-commits/quintpact-vas/blob/v2.11.1/docs/PROJECT-ROOT.md)

## What happens in the chat

| What you ask | Expected behavior |
| --- | --- |
| Index an empty starter | Inspect the project and explain the evidence for a new app. Ask who will use it and what they need to do first. |
| Index an existing app | Identify a relevant feature from actual code, then ask what should change. Keep the existing design unless the requested scope changes it. |
| Show only the folder structure | Report the inspected structure and finish without setup questions or file edits. |
| Discuss a possible app | Keep the details already supplied. Ask one or two questions at a time about decisions that affect the work, such as the execution environment or what a passing result should look like. |
| Build the agreed app | Implement in `src/` and check the agreed behavior using the host's available tools. Report what ran, what passed and what still needs attention. |

For example, a fresh Codex chat identified an empty starter from `src/.gitkeep` and asked, “누가 어떤 일을 할 때 쓰는 앱인가요? 가장 먼저 가능해야 할 기능은 무엇인가요?” After the user described a minutes-to-seconds tool and asked to discuss it first, the agent proposed a conversion check and asked about the interface and decimal inputs. No project files changed during those first two turns. When the user requested a Python command-line app, the agent created `src/minutes_to_seconds.py`. The host and a separate process both confirmed the outputs `180초` for `3` and `0초` for `0`.

## Claude Code support

The starter includes the same project instructions in root `CLAUDE.md` and `AGENTS.md`. It also ships the design-analysis skill under `.claude/skills/design-analysis/` and scoped implementer, designer and reviewer instructions under `.claude/agents/`. Start an authenticated Claude Code session in the extracted root and send the message above. Claude Code documents project-level `CLAUDE.md` discovery and lets you inspect loaded instructions with `/context`. [Claude Code project instructions](https://code.claude.com/docs/en/memory)

Claude Code 2.1.316 ran `/context` in the extracted starter built at `7eca102`. It listed `CLAUDE.md` under Project Memory, `design-analysis` under Project Skills and `vas-designer`, `vas-implementer` and `vas-reviewer` under Project Agents. The model request stopped at authentication, so the Claude model's first setup question remains unverified. The three-turn conversation above ran in Codex.

## Verification scope

- **Actual Codex runs.** The chat instructions shipped in this patch were exercised from the Windows starter built at `7eca102`. Four scenarios covered a three-turn setup and implementation, an existing app, a structure-only request and a first turn with ordinary workspace permissions. The implementation added one app file, with all 305 existing VAS engine files unchanged. The ordinary-permission check obtained the setup questions without adding any writable roots.
- **Archive checks.** The package suite checks that all five host entry files carry the maintained project instructions. In empty and existing app fixtures it runs the documented opening reads, checks the project files and confirms that those reads alone create no private session state.
- **Private session limits.** The restricted Windows Codex setup could implement and verify the sample in the current chat, but session creation returned `session_store_unavailable`. A separate resume lookup returned `session_not_found`. A new chat can inspect existing application files. Restoring prior decisions, checks and progress from VAS requires a successful private-session save and read on the same PC and installation.
- **Release checks.** The tag-triggered release workflow verifies the Windows runtime and extracted starter before running the remaining checks and publishing the ZIPs. Use the workflow run for this tag to inspect its results. [Release workflow](https://github.com/zmsqnfl-commits/quintpact-vas/actions/workflows/release.yml)

The standalone `VAS-Client-Form-2.11.1.zip` is the shareable request form. `SHA256SUMS.txt` and `release-manifest.json` identify the published assets. The [2.11.0 release notes](https://github.com/zmsqnfl-commits/quintpact-vas/blob/v2.11.0/docs/releases/2.11.0.md) describe the project layout, saved prompt and reference-analysis features used by this patch.
