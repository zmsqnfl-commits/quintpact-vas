# VAS 2.13.2 — Resume remote sessions and report checks once

## Continue across remote shell calls

Some connected-folder hosts remount a project between commands. VAS now recognizes a writable project enrolled during session creation or explicit rebinding using its path, directory identity and a project-specific witness. A device-number change alone no longer forces repeated rebinding or increments the session revision. Replaced targets still require confirmation. Older sessions may need one explicit rebind to enroll. The project journal remains available to hosts with separate private session stores.

## Finish a prepared task

Keep the `finishArguments` from the successful preparation before editing. Supply that argument list to `scripts/vas.py` with the actual summary, checks, remaining work and criterion observations. VAS generates a result ID, builds the v1 report, assesses it against the prepared handoff and reads back the checkpoint. Use the tested artifact's version when reporting a criterion. A changed handoff requires a fresh comparison. Failed or skipped criterion IDs and their reported reasons carry into the shared progress note. Missing checks remain outstanding, and an agent's report never records user acceptance.

Hosts that supply complete v1 reports can keep using that format. Invalid reports now give a field-specific diagnostic. Progress can distinguish a check that did not run while mapping it to the v1 skipped state. Notes also retain relative Docker volume notation such as `./:/app`, while private host paths are masked.
