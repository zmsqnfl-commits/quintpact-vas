# VAS 2.7.4 — Connected workflow and credential boundary recheck

VAS 2.7.4 strengthens the path from requirements and design selection to copied instructions, optional JSON, and work-memory recommendations. It preserves handoff v3, result v1, saved design keys, and the stable `VAS-source` folder name.

## Credential and memory protection

- **Multi-line and concatenated credentials are withheld.** Browser and Python cleaners remove triple-quoted values, including prefixes, line breaks, escaped delimiters and unfinished strings. Adjacent, concatenated or parenthesized credential expressions have no reliable scalar boundary in free text and are withheld as a whole input.
- **Encoding cannot bypass work-memory filtering.** Browser and Windows memory boundaries check quoted JSON, credential aliases, database driver URLs, encoded paths and metadata. Values that still require decoding after the bounded decoder are withheld. Ordinary confirmed design choices remain usable.
- **Historical records are filtered when read or exported.** Recommendations derive their profile from currently filtered events instead of a persisted profile cache. This protects outgoing data from older, weaker filters. It does not claim to erase historical files already outside the application.
- **Knowledge filtering runs before path rewriting.** Encoded JSON reaches the credential cleaner before backslashes can be mistaken for paths. Only knowledge schema 3 is accepted for search and handoff; older materialized indexes may contain unlabeled remnants and require explicit regeneration with the compatibility tool. VAS does not automatically read or reindex user projects.

## Connected workflow fixes

- A successful event write no longer fails because a secondary recommendation-profile write failed. Erasure retires the old profile cache before deleting events, so a cache failure is reported before primary data is changed.
- Clearing memory or changing consent invalidates in-flight design-confirmation state. A delayed completion cannot overwrite the current confirmation or cause a duplicate retry.
- The optional result-import library ignores obsolete file reads and cancels a previous dialog-close timer when a new review begins. Missing receipts or blocked storage cannot cause the same manually confirmed result to be accepted twice in one page session.
- Inherited JavaScript object names such as `constructor` cannot select a taste profile or break prompt generation. Normal manual profiles continue to work.
- The handoff guide now accurately states that reference files contribute a count, without names or contents.

## Validation and scope

The shared suite contains **55 synthetic credential cases**, exercised through browser and Python handoffs, project knowledge, and Windows work-memory boundaries. Browser regressions also cover historical exports, storage failures, delayed confirmations, competing file reads, duplicate acceptance, and normal design controls.

Local Windows validation passed **245 Python checks with one symlink-permission skip** and **96 browser scenarios**. The package gate checks reproducibility, included files, checksums and standalone assets; the extracted Windows runtime and release-boundary checks run before publication. GitHub Actions provides the final Linux/Windows release gates. The optional ten-repeat stress suite was not requested.

**Follow-up on 2026-09-08:** With administrator authorization, the previously skipped directory-symlink check passed on Windows: **1 passed, 0 skipped**. It created a real link to a synthetic outside directory and verified that analysis reports the link as excluded and project import does not copy it. The test and implementation were copied directly from release commit `84cc5a90001bd7e59dcf4eb1f6227d441267d8a9`; their hashes matched before and after execution. The combined Python coverage is now **246 passing checks with no unresolved permission skip**. This follow-up changes documentation only; the v2.7.4 tag and release ZIPs remain unchanged.

The source assessment reviewed **109 of 284 tracked files** at the pre-fix revision in full. The remaining files include passive assets, historical/reference documents and most test files. A separate read-only candidate review identified additional cases, which were incorporated into the fixes and regressions. This is a scoped assessment with integration tests, not a complete security certification.

Format-free text can be ambiguous: for example, a backslash before a closing TOML literal delimiter also resembles an unfinished Python string. VAS may withhold the entire ambiguous credential-bearing input, including otherwise harmless following settings. Review the final prompt and enter those settings separately. Arbitrary secrets without recognizable labels or formats are not guaranteed detectable.

Without a durable receipt, duplicate-result protection lasts for the current page session. A disconnected persistent memory service still requires recovery before a consent change can be acknowledged. Existing source/recovery backups and saved drafts are distinct from exported work memory. External coding-host execution, OS/NAS permissions and previously shared files are outside these checks. Role instructions and hashes do not prove that a coding host executed an agent or passed tests.

## Upgrade

Update the existing `VAS-source` checkout or extract the new Windows ZIP. Close the old VAS session and launch it again to load the updated backend. Preserve existing user data and design selections. Versions belong on release artifacts; the working folder name stays stable.

The default flow remains: choose memory use, describe the task, confirm a design, copy the prompt, and continue in the coding host. JSON download and legacy result review are optional. The coding host owns source inspection, implementation, review and execution verification.
