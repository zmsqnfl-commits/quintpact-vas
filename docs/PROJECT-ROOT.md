# 받은 폴더로 앱 시작하기

1. 저장소를 새 위치에 복제하거나 GitHub **Code → Download ZIP** 또는 **Windows 프로젝트 ZIP**을 새 폴더에 모두 풉니다. `project-layout.json`, `Run-VAS-System.bat`, `src/`가 직접 들어 있는 폴더를 열고 첫 세션 전에 원하는 프로젝트명으로 바꿉니다.
2. 그 폴더 자체를 코딩 AI에서 열고 “폴더 전체 색인해줘”라고 요청하세요. AI가 현재 앱의 상태를 확인하고 채팅에서 작업 설정을 시작합니다. 앱 코드는 최상위 `src/`, VAS 설정 화면은 `ui/`, 명령은 `scripts/`, 안내는 `docs/`에 있습니다.
3. VAS 화면이 필요하면 루트의 `Run-VAS-System.bat`를 실행하세요. VAS 설정 화면은 앱과 별개입니다. 새 앱의 코드·자산·의존성·컨테이너 설정·빌드 결과는 모두 최상위 `src/` 안에 둡니다. 예를 들어 `src/package.json`, `src/compose.yaml`을 사용하고 설치·실행·테스트·빌드는 `src/`에서 합니다. 기존 앱의 설정 파일은 현재 위치를 먼저 확인하고 보존합니다.

Claude Code를 쓰면 압축을 푼 프로젝트 루트에서 세션을 시작하고 같은 문장을 입력하세요. 최상위 `CLAUDE.md`에 채팅 시작 지침이 들어 있습니다. Codex의 최상위 `AGENTS.md`에도 같은 내용이 제공됩니다.

## 처음 열거나 이어갈 때

에이전트는 열린 프로젝트 루트에서 다음 명령을 실행합니다. Windows와 Linux에서 Python 3.10 이상을 사용합니다.

```text
python -B scripts/vas.py start
```

- `app.state`는 앱 폴더가 비어 있는지 또는 항목이 있는지 알려줍니다. 항목이 있으면 앱의 실제 진입점·지침을 직접 확인하세요. 설치 의존성·비밀값·운영 데이터까지 읽는 전체 색인을 요구하지 않습니다.
- `projectPrompt`는 화면에서 마지막으로 저장한 지시와 판본입니다. 판본 0이면 저장된 지시가 없습니다. `session.status`가 `none`이면 현재 폴더의 첫 대화를 시작하세요. 어디서 무엇을 만들지 `nextAction`과 실제 요청을 함께 보고 정합니다. 저장소 권한이나 기록 오류는 첫 프로젝트로 처리하지 않고 어느 조회가 실패했는지 알립니다.
- 새 앱의 목적이 정해지지 않았으면 사용자와 첫 기능을 묻습니다. 이전 앱이 언급됐고 이전 의사가 불분명하면 “새로 만들까요, 기존 앱을 이어갈까요?”라고 묻습니다. 이전하라고 명시했으면 이미 결정한 내용을 다시 묻지 않습니다. 앱 복사 범위·완료조건을 확인하고 키 복사나 NAS 동기화까지 추정하지 마세요.
- 색인·계획 요청은 읽은 상태나 다음 결정에서 멈춥니다. 실제 구현 요청과 범위·완료조건이 합의되면 `scripts/vas-session.py`의 `create --target .` 또는 `save`로 합의한 설정을 저장합니다. `resume --session ID`로 같은 내용을 읽고 `prepare`가 `prepared`일 때 편집합니다. `needs-input`이면 막히는 결정만 확인합니다. 화면의 지시 변경도 구현·위임 직전에 다시 조회하세요. [인계와 검증](CHAT-EXECUTION.md) · [세션 설정 예시](CHAT-STATE.md)

호스트가 바뀌면 개인 세션이 없을 수 있습니다. 같은 작업 폴더에 마지막 `finish`가 남긴 `vas-state/progress/` 요약이 있으면 `start`로 읽고 현재 앱 원본과 대조하세요. Windows에서 루트의 Run-VAS-System.bat로 연 허브의 **프로젝트 진행 요약**에서도 공유 판본·검사·다음 행동을 읽을 수 있습니다. “요약 없음”과 “읽지 못함”은 다른 상태입니다. 이 요약은 개인 세션 전체를 복원하지 않습니다. 새 작업 지시는 루트의 `VAS-PROJECT-PROMPT.json`에서 따로 읽습니다.

새 `finish`는 같은 판본의 JSON과 사람이 읽을 Markdown을 함께 남깁니다. 예를 들어 `vas-state/progress/000001.md`는 첫 완료 판본의 보기 파일입니다. CLI가 막히면 실패한 조회를 알리고 가장 높은 완료 표식(`.ok`) 번호의 `.md`를 직접 열어 지금 앱과 대조합니다. 예전 JSON 판본에 Markdown이 없으면 과거 파일을 다시 쓰지 않습니다.

준비한 작업에서는 합의한 목표·완료조건을 기록합니다. 작은 수정은 앞서 확인한 범위를 보존하며, 결정·남은 일·검사는 실제 기록이 있을 때 표시합니다. Windows 허브는 이 항목과 읽을 수 있는 파일 경로를 보여줍니다. Markdown은 저장한 요약에서 생성되므로 파일 자체를 편집해 요구사항을 바꾸지 않습니다. 사용자가 앱의 자체 `spec.md`나 `plan.md`를 사용하라고 하면 그 파일을 프로젝트 자료로 읽습니다. 이 과정에 별도 규격 문서 세트나 설치가 필요하지 않습니다.

이전 앱 원본을 지정한 경우 [마이그레이션 안내](MIGRATION.md)의 읽기 전용 미리보기로 코드 범위를 확인한 뒤 합의된 파일만 적용하세요.

Claude Code의 [시작 훅](CLAUDE-START-HOOK.md)은 선택 사항입니다. 훅이 실행되지 않는 호스트에서는 같은 `start` 명령을 직접 사용합니다.

## 작은 수정

수정 위치가 확인된 문구 하나나 작은 스타일 변경은 `start`로 현재 상태를 읽고, 요청된 부분을 수정한 뒤 실제로 검사합니다. 그 결과는 세션을 만들 필요 없이 짧은 `finish`로 기록할 수 있습니다. 아래 명령은 해당 표시를 직접 확인한 경우의 예입니다.

```text
python -B scripts/vas.py finish --summary "메뉴판 제목 문구 수정" --check "메뉴판 제목 표시: 통과" --next-step "다음 작업 확인"
```

`--check`는 실제 결과에 따라 `통과`, `실패`, `미실행`, `건너뜀`을 구분하고 여러 번 지정할 수 있습니다. 이 요약은 호스트의 검사 보고입니다. 파일 여러 개, 저장 데이터, 앱 이전이나 배포를 바꾸는 작업에는 합의한 세션과 준비 절차를 사용합니다.

## 준비한 작업을 마치거나 중단할 때

에이전트가 실제로 준비한 세션과 최신 판본을 사용해 아래 명령에 UTF-8 JSON을 표준입력으로 전달합니다. 사용자가 입력 파일이나 결과 JSON을 만들 필요는 없습니다.

```text
python -B scripts/vas.py finish --session ID --expected-revision N --expected-progress-revision P
```

`ID`와 `N`은 해당 작업의 세션 ID와 설정 판본, `P`는 마지막 조회에서 확인한 진행 판본입니다. 첫 진행 기록은 0입니다. 저장한 프로젝트 지시를 읽고 작업했다면 `--expected-project-prompt-revision R`도 전달합니다. `R`에는 실제 확인한 지시 판본을 씁니다.

입력의 `result`에는 준비한 인계와 대조할 실제 결과 보고서를, `progress`에는 [진행 요약](CHAT-PROGRESS.md)의 단계·검사·남은 작업을 담습니다. 검사하지 못한 항목도 표시합니다. 결과 보고서를 만들 수 없는 상황에서 중단하거나 막혔으면 예시처럼 `result`를 `null`로 전달합니다.

```json
{"result":null,"progress":{"phase":"blocked","summary":"이전할 앱 원본이 아직 지정되지 않았습니다.","nextStep":"원본 폴더와 복사할 파일 범위를 확인합니다."}}
```

평가, 저장한 판본·다음 행동의 재확인 결과를 읽은 뒤 답합니다. 기존 공유 기록을 읽었다면 그 판본을 `--expected-shared-revision N`에 전달합니다. 처음 저장할 때는 0입니다. 결과 보고가 없으면 평가도 없습니다. 후속 검사나 실패가 남으면 그 상태로 전달합니다. 판본 충돌이나 저장 실패를 완료로 표시하지 마세요. 다른 AI의 과거 작업을 등록할 때는 그때의 보고와 이번에 다시 실행한 검사를 구분합니다.

## 프로젝트 지시 수정

VAS 시작 화면의 **프로젝트 작업 지시**에 원하는 기능과 지켜야 할 조건을 적고 저장하세요. 아래의 저장된 내용이 실제 에이전트에게 전달할 지시입니다. 저장 성공을 확인한 뒤 채팅에서 “저장한 지시로 진행해줘”라고 하면 됩니다. 화면 저장만으로 실행 중인 AI를 깨우거나 작업을 중단시키지는 않습니다.

지시는 프로젝트 루트의 `VAS-PROJECT-PROMPT.json` 한 파일에 저장합니다. AI가 첫 요청과 다음 작업·위임 전에 읽고, 완료조건과 작업 계획에 반영합니다. 파일을 프로젝트와 함께 복사하면 지시도 함께 전달되므로 비밀값·연락처·개인 경로는 넣지 마세요. 이 파일은 개인 대화·진행 기록을 복사한 것이 아닙니다.

다른 탭이 먼저 저장하면 이전 화면의 저장은 거부하고 편집 중인 내용을 유지합니다. 최신 저장 내용을 다시 불러와 수정하세요. 저장 실패와 손상된 파일도 성공으로 표시하거나 자동 덮어쓰지 않습니다. 지시를 없애려면 입력을 비운 뒤 저장합니다. 저장한 지시와 현재 채팅의 명시적 변경이 충돌하면 그 차이만 확인합니다.

연결된 작업의 인계를 준비할 때는 이 지시와 버전이 함께 들어갑니다. 다른 앱 경로를 명시한 작업에는 이 프로젝트의 지시를 섞지 않습니다. 이전 지시에 대한 검사 결과는 새 지시의 검증으로 재사용하지 않습니다.

이름 변경은 **첫 세션을 만들기 전**에 하세요. 이미 세션을 저장한 뒤 설치 위치를 바꾸면 이전 PC 전용 기록이 자동 이전되지 않습니다. 앱 파일은 파일시스템에 그대로 있습니다. 새 ZIP을 기존 앱 위에 풀어 덮어쓰지 마세요.

호스트에서 앱 파일을 수정할 수 있어도 PC 전용 저장소에 쓸 권한은 별개입니다. `session_store_unavailable`이면 앱 작업은 가능하지만 진행 기록이 저장되지 않았으므로 새 대화에서 자동 재개됐다고 볼 수 없습니다. 세션 파일을 프로젝트 안에 넣거나 권한을 풀지 마세요.

프로젝트 지시는 위의 공개 가능한 파일에서 읽으므로 PC 전용 세션을 만들기 전에도 사용할 수 있습니다. 따라서 **프로젝트 지시 읽기 성공**과 **대화 진행 저장 성공**을 구분합니다.

이 구조는 2.12.1부터 GitHub 소스 ZIP과 Windows 프로젝트 ZIP에 공통으로 적용됩니다. VAS 자체를 수정하는 경우에는 `.agents/DEVELOPMENT.md`를 따릅니다. 이전 버전 앱을 옮길 때는 [새 폴더 업그레이드](MIGRATION.md)를 참고하세요.
