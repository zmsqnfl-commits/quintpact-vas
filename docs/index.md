# VAS 2.10.0 시스템 지도

## 사용자 흐름

AI에서 VAS 폴더 열기 → 작업 종류·실제 대상 구분 → 설정·최신 진행 복원 → 차단 질문 정리·최신 인계 준비 → 범위와 선택 파일을 연결한 실제 구현·역할 회수·검사 → 원래 조건과 결과 대조 → 필요한 후속 행동 → 진행 요약 저장·재조회로 이어집니다. 같은 PC의 같은 VAS 설치에서 새 대화로 계속할 수 있습니다. 디자인 화면은 필요한 작업에서 선택합니다.

[대화로 시작하기](CHAT-START.md), [설정 저장과 재개](CHAT-STATE.md), [진행 요약](CHAT-PROGRESS.md), [실행 기록](CHAT-WORK.md), [평가 후속 행동](CHAT-FOLLOWUP.md), [구현과 검증](CHAT-EXECUTION.md)을 참고하세요.

기존 화면 설정 흐름:

```text
Run-VAS-System.bat
  -> 시작 화면
     -> 새 프로젝트 -> 요구사항 -> 디자인 -> 프롬프트 복사
     -> 기존 프로그램 -> 폴더 위치 -> 작업 작성 -> 디자인 -> 프롬프트 복사
  -> 코딩 도구에서 RBG 확인 후 실제 작업
```

기존 웹 화면은 프롬프트와 선택 JSON을 만듭니다. 로컬 디자인 스튜디오는 저장된 채팅 작업을 선택해 디자인을 함께 사용할 수 있습니다. 앱 실행이나 배포를 관리하는 프로젝트 대시보드는 제공하지 않습니다. 이번 버전의 변경과 지원 범위는 [2.10.0 릴리스 안내](releases/2.10.0.md), 실제 점검 범위는 [에이전트 흐름 검증 기록](verification/2.10.0-agent-flow.md)에 있습니다.

## 2.10.0 연결 흐름

- 참고 질문 `questions`와 구현을 막는 `blockingQuestions`를 구분합니다. 두 목록과 실제 `nextStep`은 인계 참고 문맥으로 전달하며 차단 질문이 남으면 준비 완료로 처리하지 않습니다.
- `checkpoint`는 최신 진행 요약과 설정의 다음 행동을 원자적으로 저장합니다. 설정·진행·실행 기록의 revision을 구분하며 충돌·손상을 자동 덮어쓰지 않습니다. 저장된 검사 통과는 현재 파일 확인을 대신하지 않습니다.
- `work start`는 실제 작업 전 범위·관찰 파일을 기록하고 `finish`는 실제 호스트 반환 뒤 결과를 연결합니다. `inspect`는 선택 파일 지문을 비교하며 실패·미회수·범위 밖 변경을 숨기지 않습니다.
- `assess.followUp`은 실패 수정, 필요한 조건 재검사, 근거 대조, 원래 직접 확인 등을 구분합니다. 관련 표본과 실행 근거가 유지되는 검사는 재사용 후보로 남기며 모든 검사를 일괄 반복하지 않습니다.
- 기존 완료 평가는 유지합니다. 자동 조건만 있는 작업에 남은 행동이 없더라도 사용자 수용을 인증하지 않으며, 그 이유로 새 수동 조건이나 승인을 만들지 않습니다.

설정·진행·실행 기록은 전체 대화 복원이나 앱 백업이 아닙니다. 실제 실행·검증·위임 회수는 코딩 호스트가 수행하며 VAS는 선택 파일 관찰과 계약 대조를 지원합니다.

## 유지되는 2.9.2 보완 사항

작업 기억의 백업·손상 원본·임시 파일에 보관 한도를 적용하고, 실패 시 기존 자료를 보존합니다. 런타임 인증 파일은 Windows 전용 권한으로 보호하며, 기억·런타임 상태는 링크가 아닌 로컬 경로에 저장합니다. 제품 원본은 NAS에서 계속 사용할 수 있습니다.

인계·작업 기억·참고 색인의 알려진 비밀값 정제를 보강했습니다. 이전 대화 설정에서 정제 규칙에 따른 차이만 발견되면 원본을 덮어쓰지 않고 안전한 사본을 보여줍니다. 주 실행자가 요구사항을 검토해 전체 설정을 다시 저장한 뒤 구현 인계를 준비합니다. 선택형 RAG는 출처가 있는 인용 데이터로 전달하며 기본 화면에 자동 추가하지 않습니다.

이전 변경의 상세 내용은 [2.9.2 릴리스 안내](releases/2.9.2.md)에 남겨 둡니다.

## 계속 유지되는 2.9.1 정책

Windows 작업 기억은 서버에서 동의를 확인하고 누적 10,000건·UTF-8 8 MiB로 제한합니다. 동의 정보가 없는 기존 저장소는 기록을 보존한 채 꺼짐으로 시작합니다. 저장소가 가득 차도 기록 끄기와 기억 없이 시작은 가능합니다. 같은 origin의 열린 탭은 동의 변경·화면 복귀 때 상태를 다시 읽습니다.

인증 없는 상태 확인·정적 조회·거부된 인증은 서버 종료 대기 시간을 연장하지 않습니다. 기존 앱 결과의 `registered`와 `existing`은 호환하지만 인계 ID·해시·회차 검증은 유지합니다. 제한 모드와 다음 채팅 안내도 보완했습니다. 자세한 한계와 복구 방법은 [운영 가이드](OPERATIONS.md)에 있습니다.

## 저장·호환

- 작업 기억: Windows 사용자 로컬 또는 브라우저 IndexedDB. Windows 동의는 기록과 별도인 `memory-consent.json`에서 관리
- 일반 디자인 설정: 브라우저 저장소와 URL 상태
- 연결된 채팅 디자인: PC의 공통 세션 저장소, 저장 전 화면 초안은 메모리만 사용
- 채팅 진행 요약·실행 기록: 공통 PC 세션 저장소에 각각 최신 한 건. 전체 채팅·원시 실행 로그·앱 파일은 보관하지 않음
- 호환용 프로젝트 백업: `.vas_backups/` 최신 10개. 채팅 `checkpoint`와 별개
- 배포물: `dist/`
- 기존 `workspace/` 프로젝트와 복사·등록 모듈은 삭제하지 않지만 기본 UI에는 노출하지 않습니다.

## 운영 원칙

- 모든 기능은 외부 CDN 없이 동작합니다.
- 브라우저 최초 저장소 초기화가 불가능하면 임시 저장임을 표시합니다. 연결된 저장소의 쓰기·삭제 실패를 성공으로 처리하지 않습니다.
- 작업 기억은 동의 없이 자동 활성화하지 않습니다.
- 최종 JSON에는 요구사항·디자인·안전 규칙·AI 안내만 포함하며 구조·기술 스택은 추정하지 않습니다.
- 기존 프로그램의 절대 경로는 복사 프롬프트에만 넣고 JSON·작업 기억에는 저장하지 않습니다.
- 대화 재개에 필요한 대상 경로는 제품 밖의 PC 전용 binding에만 저장하며 공유 설정·브라우저 응답에는 포함하지 않습니다.
- 화면 저장은 AI를 실행하지 않습니다. 다음 요청·구현·위임·저장 전에 주 실행자가 최신 세션을 재조회합니다.
- 실행 인계 준비와 결과 대조는 앱 코드를 실행하지 않습니다. 실제 원본 확인·구현·역할 호출·테스트는 코딩 호스트가 수행합니다.
- 대화 실행 결과는 현재 세션·revision·설정·역할 자료에 연결한 인계와 대조합니다. 오래된 결과의 ID만 바꿔 최신 작업의 증거로 재사용하지 않습니다.
- 선택 파일 지문은 그 파일의 관찰 시점만 확인합니다. 실제 명령 실행·전체 프로젝트 무변경·외부 환경 동일성을 인증하지 않습니다. 문맥 변경과 파일 변경을 구분합니다.
- 후속 행동은 읽기 전용 참고 자료이며 자동 실행·저장하지 않습니다. 주 실행자는 실제로 남은 행동을 수행하고 최신 상태를 조회해 진행 요약을 저장·재조회합니다.
- AI 보고·VAS 평가·사용자 확인을 구분합니다. 대화 실행 CLI는 사용자 직접 확인을 입력받지 않으며 보고만으로 완료를 인증하지 않습니다.
- 기본 저장·복사는 인계 영수증을 만들지 않습니다.
- 호환용 반복 계약은 ID·해시·sourceType과 중복을 검사합니다. 로컬 영수증이 없을 때는 사용자 수동 확인이 필요하며, 확인된 불일치·중복은 수동 확인으로 우회할 수 없습니다.
- 해시는 입력 일관성을 확인합니다. 실제 에이전트 실행·권한·테스트 성공의 증명은 코딩 호스트의 실행 결과에서 별도로 확인합니다.
- 파일은 500줄 이하로 유지합니다.

상세 범위·완료 판정·호환 정책: [작업 범위와 완료 확인](completion-policy.md).
