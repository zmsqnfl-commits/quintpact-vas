# 작업 범위와 완료 확인

VAS는 작업 지시를 전달하고 확인 근거를 구분하는 도구입니다. 코딩 AI의 실제 실행과 권한은 해당 호스트가 담당합니다.

## 기본 작업 흐름

1. 새 작업 또는 기존 작업의 요청과 완료조건을 작성합니다.
2. 조건별 확인 방법을 선택합니다. 자동 검사, 실제 산출물 수동 확인, 정적 검토를 구분합니다.
3. 기존 작업은 디자인 유지가 기본입니다. 요청 기능에 필요한 UI는 기존 컴포넌트와 규칙으로 추가합니다.
4. 부분 디자인 수정은 허용 화면·요소·속성을 지정합니다. 전체 리디자인도 데이터 삭제나 기능 변경을 허가하지 않습니다.
5. 정제된 최종 지시를 확인하고 프롬프트를 복사합니다. JSON 저장은 선택입니다.

저장된 디자인 프리셋은 유지 모드에서도 보존하지만 현재 작업의 활성 지시에는 포함하지 않습니다. 과거 인계에 범위가 없으면 과거 의도는 미상입니다. 새 작업 기본값으로 과거 인계 내용을 덮어쓰지 않습니다.

완료조건을 입력하지 않았을 때 기본 안내 문장은 검증 방법을 설명할 뿐, 해당 작업의 충족 증거가 되지 않습니다. 확인할 조건이 없는 상태를 자동 완료로 계산하지 않습니다. 변경이 불필요한 작업도 그 판단 자체를 확인할 조건으로 적습니다.

## 세 가지 상태

| 상태 | 뜻 |
|---|---|
| 에이전트 보고 | AI가 제출한 작업 상태. 실행 증거가 아님 |
| VAS 평가 | 조건과 별도로 확보한 확인 기록으로 평가한 상태 |
| 사용자 수용 | 결과를 다음 작업에 사용하거나 부족한 검증을 알고 받아들임 |

다음 작업으로 연결하거나 사용자 수용을 선택해도 실패·미확인이 검사 통과로 바뀌지 않습니다.

| 평가 | 기준 |
|---|---|
| 평가 불가 | 입력 형식 오류, 미지원 계약, 인계 불일치 |
| 미완료 | 미해결 blocker, 실패 테스트, 필수조건 실패 또는 범위 위반 |
| 확인 필요 | 조건·필수 근거 누락, 자기보고만 존재, 필요한 검사 미실시 또는 대상 버전 불일치 |
| 완료 | 합의한 필수조건을 해당 버전의 실제 확인 근거로 충족하고 blocker 없음 |

미완료 원인이 있으면 단순 근거 누락보다 우선합니다. 기존 결과의 `status`는 실패 테스트가 있으면 `incomplete`로 정규화하는 호환 동작을 유지하며, `reportedStatus`에 원래 입력 상태를 별도로 보관합니다. 가져온 JSON의 별도 `reportedStatus`를 믿는 것이 아니라 원래 `status`에서 얻습니다.

## 근거의 의미

확인 방법과 수집 출처는 서로 다릅니다. AI가 자동 테스트 통과라고 쓰거나 로그·스크린샷·해시·CI 주소를 제출해도 VAS의 사용자 확인 기록으로 승격하지 않습니다.

- 에이전트 제출 근거: 검토할 자료이며 자체적으로 완료를 증명하지 않음.
- 사용자 직접 확인: 조건·산출물 버전·방법·관찰 결과·시점을 별도 기록.
- 독립 실행 수집: 이번 범위에 포함하지 않음. 향후 신뢰하도록 설정한 호스트나 CI의 특정 실행을 직접 조회해야 함.

자동 테스트가 적용되지 않는 문구·문서·시안 작업은 실제 산출물 대조로 확인할 수 있습니다. 기능 수정의 실행 확인을 코드 읽기만으로 대신하지 않습니다. 필요한 검사를 건너뛴 경우와 검사 방법이 대상이 아닌 경우를 구분합니다. 대체 확인을 사용하더라도 실제 확인 대상과 결과가 필요합니다.

사용자 확인은 제출 JSON과 별도 영역에 저장하며 결과 내용·인계·산출물 버전에 연결합니다. 다른 결과에 이전 확인을 재사용하지 않습니다. 로컬 기록은 암호학적 실행 증명이 아니며, 사용자가 실제 산출물을 확인했다는 기록입니다. 사용자가 브라우저 저장소를 지우면 해당 확인 기록도 유지되지 않습니다.

필수조건은 원래 인계에서 읽습니다. 에이전트가 결과에서 조건을 선택사항으로 바꾸거나 blocker를 임의로 제외하여 완료시킬 수 없습니다. 조건을 바꾸려면 수정한 조건으로 새 인계를 만들고 다시 평가합니다. 결과 수용은 조건 변경 승인이 아닙니다.

## 호환·개인정보

인계 v3와 결과 v1을 유지합니다. 새 범위와 완료조건은 기존 소비자가 읽는 프롬프트·문자열 완료조건에도 전달합니다. 기존 결과에 근거가 없으면 확인 필요로 표시하고 없는 확인 결과를 만들지 않습니다.

일반 검증은 숫자형 계약 버전·반복 번호와 배열 항목·한도를 엄격히 검사합니다. 잘못된 항목이나 한도 이후 실패를 버리고 완료 처리하지 않습니다. 이전 구현이 허용한 숫자 문자열 등은 명시적인 복구 단계에서 변경 내용을 확인한 후 변환하며 정상 검증을 느슨하게 만들지 않습니다.

자동 정제, 사용자 확인, 독립 보안 검증을 별도로 표시합니다. `privacyChecked` 같은 과거 플래그와 인계 연결 `verified`는 독립 보안 검사·실행 검증 통과가 아닙니다. 확인 기록에도 비밀값·연락처·절대 경로·원시 명령 출력을 저장하지 않습니다.

결과 회수는 기본 화면에 노출하지 않는 호환 기능입니다. 기본 사용자는 결과 JSON 제출을 강요받지 않으며 프롬프트를 전달한 뒤 코딩 도구에서 작업을 계속합니다.
