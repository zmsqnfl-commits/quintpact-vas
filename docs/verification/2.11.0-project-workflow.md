# VAS 2.11.0 project workflow verification

This record distinguishes VAS product regressions, release packaging and observed coding-host/application behavior. A passing contract or package test is not proof that every external AI follows the instructions, and a saved report is not proof that a command ran.

## Final versioned source checks — 2026-11-02

The complete required source checks were rerun locally after the 2.11.0 version and current documentation updates, using Windows, Python 3.14 and installed Chrome.

| Check | Observed result |
| --- | --- |
| `npm run test:python` | Passed; pytest reported 1,539 passes, 3 symlink-privilege skips and 1 deprecation warning. Required form, syntax, integrity and personalization checks also passed. |
| Standalone Windows runtime / runtime-source checks | 14 / 4 passed within the Python command above |
| `npm run test:browser -- --workers=2` | 198 passed, without a retry in this final run |
| Connected Windows CLI/design posttest | 17 passed, separate from the 198 Playwright tests |

The three skipped cases require link-creation privileges and are not counted as passes. The deprecation warning concerns pytest parameter collection, not a failed assertion. Package creation follows the release commit so the embedded manifest identifies that commit. The matching [release workflow](https://github.com/zmsqnfl-commits/quintpact-vas/actions/workflows/release.yml) records its additional Windows, Linux and package gates before publishing assets; a successful local run alone does not establish hosted publication.

## What the workflow checks cover

- A Windows starter has user application `src/`, isolated `.vas/` tools, host entry instructions and bundled design-analysis skills. The source repository keeps its developer layout.
- Saved project instructions travel through the root prompt file, screen, CLI read and prepared task context. Revision conflicts, invalid files and inaccessible private session stores remain visible.
- Visual-only sample policy reaches browser and chat instructions while preserving actual task requirements and design-change scope.
- Image-analysis instructions require direct source inspection, observed/proposed distinctions, component mapping and actual rendering checks.
- Existing session, privacy, work records and assessment contracts remain subject to their regression suites. No automatic claim of image inspection or app completion follows from contract validation.

## Fresh host attempts and independent application checks

Two fresh coding-host exercises used Bento and Swiss visual directions for an inventory application. Both produced app files but reached the 480-second host deadline after attempts involving restricted browser or private-session access. Neither is reported as a fully completed autonomous workflow.

A separate verifier opened the produced apps in actual Windows Chrome using local HTTP, inspected screenshots and checked behavior. An external-reference example from the prior image-analysis exercise was also inspected. That reference was a cream, olive and orange composition with serif type and a plant image, not a built-in VAS preset.

The verifier distinguished original output from corrected example output. The findings below were fixed in isolated example applications; they are not global VAS CSS changes or automatic changes to users' apps.

| Example | Observed problem | Correction and observed result |
| --- | --- | --- |
| Bento | Bricolage declared but not actually loaded for Latin text/numbers; long names and large totals crowded narrow cards | App-owned font file and OFL added; actual Bricolage use confirmed with Korean fallback recorded. Name/control rows and size rules adjusted for long data and intermediate card widths. |
| Swiss | Placeholder text on blue measured 4.29:1; a large quantity split at 320 px | Readable existing text token measured 7.98:1. Intrinsic columns and narrow-screen numeric sizing kept the quantity readable. Actual Anton title use and Korean fallback were checked. |
| External image | Three text/background pairs measured 3.70:1, 4.18:1 and 3.49:1; long quantities crowded the layout | Text variants measured 5.07:1, 6.40:1 and 4.83:1. Quantity layout was corrected, including intermediate-width behavior. Serif Korean titles and body fallback were observed separately. |

Common viewport checks used **1440, 390 and 320 CSS px**. Targeted breakpoint checks also covered Bento widths 680/681/1000/1001 and external-reference widths 640/641/768/900. Tests exercised empty, normal, 80-character Korean text and large-number states as appropriate to each example, including main actions and persistence after reload. Keyboard checks and relevant example-specific interactions were performed separately from screenshots.

The corrected examples retained the chosen visual elements while implementing the inventory request. They did not inherit unrelated shopping, subscription, exhibition or contact functions from the reference material. VAS tooling and original source hashes were preserved during the separate application checks.

## Limits of this evidence

- Windows Chrome viewport resizing is not physical-device testing. Android, iOS and Safari were not covered by these observations.
- The examples ran over local HTTP. A `file://` double-click path was not verified.
- Sampled text contrast and narrow-layout checks do not certify full accessibility conformance.
- Host timeouts and unavailable tools remain failures or unavailable evidence. Independent follow-up checks do not retroactively turn those host runs into completed end-to-end executions.
- The external-image host exercise preceded the final guidance revision. Strengthened instruction transport and regressions were checked, but all fresh application generations were not repeated against the final wording.
- Font availability, scripts, runtime permissions and image/browser access depend on the coding host and the actual app. A bundled skill cannot grant those capabilities.
- The public source includes this scoped summary, not private host transcripts, session stores, runtime tokens or local evidence directories.
