# 샘플은 디자인 요소로 참고하기

VAS 2.13.0 프로젝트 배포본에는 샘플의 디자인과 앱의 기능을 분리하는 인계 규칙이 포함됩니다. 이전에 복사한 프롬프트는 자동 갱신되지 않으므로 새 인계를 준비합니다.

직접 가져온 이미지는 기본 탑재된 [디자인 분석 스킬](DESIGN-ANALYSIS.md)로 실제 원본을 확인하고 요소별 적용까지 이어갑니다.

## 가져올 것과 직접 정할 것

| 샘플에서 참고할 요소 | 실제 프로젝트에서 정할 내용 |
| --- | --- |
| 글꼴의 성격, 제목과 본문의 크기 관계 | 현재 앱의 제목·레이블·안내 문구 |
| 색상 역할, 대비, 강조 위치 | 확정 토큰과 앱 상태에 맞춘 색상 적용 |
| 정렬, 정보 계층, 화면 밀도, 반응형 배치 | 요청한 기능에 필요한 화면과 구성 요소 |
| 이미지의 비율·크롭·질감·시각적 무게 | 앱에 맞는 이미지·도형·실제 자산 |
| 여백·간격·반복 리듬 | 실제 데이터와 입력 항목 수에 맞는 배치 |

요금제·결제·로그인·쇼핑·공연 목록·칸반·문서 편집 등은 샘플에 보인다는 이유만으로 추가하지 않습니다. 사용자 요청·저장한 프로젝트 지시·제약사항·완료조건이 기능의 기준입니다. 사용자가 같은 기능을 요청했다면 그대로 구현합니다. 기능 이름을 찾아 일괄 삭제하는 방식은 아닙니다.

예를 들어 재고 앱에서 Subscription Studio를 선택하면 밝은 바탕, 남색 글자, 푸른 강조, 정렬된 행과 여백을 품목 목록·수량 입력·합계에 적용합니다. 요금제 선택기나 결제 화면을 만들 필요는 없습니다. Retro Sunset을 고른 달력은 따뜻한 색과 굵은 제목·곡선 표현을 사용할 수 있지만 음반·공연 목록을 복제하지 않습니다.

## 인계와 구현

1. 에이전트는 최신 작업 지시와 허용된 디자인 범위를 읽습니다.
2. 선택한 요소가 실제 앱의 어느 화면·요소에 쓰일지 짧게 정리합니다.
3. 화면 복사·JSON과 대화 `prepare`는 같은 `context.design.referenceUsage` 규칙을 전달합니다. `mode`는 `visual-elements-only`, `sampleFeatures`는 `not-requirements`입니다.
4. 구현자·디자이너·검토자는 디자인 일치뿐 아니라 요청에 없는 샘플 기능이 들어갔는지도 확인합니다.

프로필과 프리셋의 내장 지침도 디자인 요소 중심입니다. 과거 인계에 기능을 지시하는 디자인 문구가 있어도 새로 준비한 프롬프트에서는 기능 요구사항으로 취급하지 않습니다. 사용자가 쓴 원본 방향·요청은 임의로 삭제하거나 고치지 않습니다. 이미 외부 채팅에 복사한 예전 프롬프트는 자동 갱신되지 않으므로 최신 인계를 다시 준비합니다.

기존 디자인 유지에서는 새 스타일을 넣지 않습니다. 부분 변경은 지정한 화면·요소·속성에만 적용합니다. 샘플의 문구·브랜드·이미지·데이터·페이지 수는 앱 요구사항이 아니며 불필요한 섹션은 생략합니다.

이 규칙은 에이전트에 전달하는 작업 범위입니다. 외부 AI가 반드시 지킨다는 실행 통제나 완료 인증은 아닙니다. 실제 산출물과 동작을 확인해야 하며, 시각 참조 링크의 전달만으로 화면을 확인했다고 보고하지 않습니다.
