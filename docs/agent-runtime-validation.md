# 2026-09-07 에이전트 실제 실행 검증

## 확인한 결과

현재 Codex 호스트에서 실제 하위 에이전트 3개를 생성하고, 검토 결과 전달·수정·재검토까지 완료했습니다.
일반 생성 도구에 VAS 역할 스킬을 명시적으로 읽게 하는 방식입니다. 네이티브 이름 기반 실행으로 기록하지 않습니다.

| 단계 | 실제 실행 결과 |
|---|---|
| Designer | 요구사항·화면 파일을 읽고 정확한 토큰, 레이아웃, 키보드 동작을 정의 |
| Reviewer | 잘못된 primary 색상과 수량 감소 버그를 독립적으로 발견 |
| Implementer | 검토 결과를 받아 CSS와 JS의 두 부분만 수정 |
| 브라우저 | 수정 전 5개 실패 → 수정 후 14개 모두 통과 |
| Reviewer 재검토 | 원본·브라우저 결과·데스크톱/모바일 캡처 확인, 남은 문제 없음 |
| 변경 범위 | 재검토 전후 요구사항·HTML·CSS·JS의 SHA-256 동일 |

실제 작업 식별자는 `/root/vas_designer_live`, `/root/vas_reviewer_live`, `/root/vas_implementer_live`입니다.
시험용 로컬 재고 화면에서 수량 10→11→12, 키보드 Space/Enter, primary #123abc, 반경 0, 패딩 24,
데스크톱 2열·390px 모바일 1열, 넘침과 JavaScript 오류를 확인했습니다.
수정 전 비교 파일은 에이전트 실행 전 저장한 해시와 바이트 단위로 일치함을 확인했습니다.

브라우저 확인 명령은 `node tests/agent-live-check.cjs <시험 폴더> <증거 폴더>`입니다.
이 명령만으로 하위 에이전트가 실행되는 것은 아닙니다. 실제 생성·결과 회수 기록과 함께 판정해야 합니다.

재현하려면 `tests/fixtures/agent-live/`의 4개 시험 파일을 새 로컬 임시 폴더에 복사합니다.
초기 시험 파일은 의도적으로 위 오류 2개를 포함하며 브라우저 검사는 종료 코드 1을 반환해야 합니다.
실제 Designer·Reviewer에게 요구사항과 시험 파일을 전달하고, 반환 결과를 Implementer에게 넘겨 그 임시 폴더만 수정하게 합니다.
브라우저 검사가 종료 코드 0을 반환한 뒤 같은 Reviewer에게 결과와 캡처를 전달해 재검토합니다.
모델 호출은 로그인된 호스트에서 명시적으로 수행하며 일반 CI는 실제 모델을 호출하지 않습니다.

## 실행 중 발견해 보완한 사항

- PATH의 Codex CLI 0.144.1은 현재 계정의 모델을 지원하지 않아 실행에 실패했습니다.
- 앱 실행기 0.153.4는 현재 모델을 사용하지만, 노출된 생성 도구에 이름 기반 역할 선택 인자가 없었습니다.
- 따라서 복사 프롬프트에 3개 역할 지침 본문을 포함하고, 실제 지원되는 일반 생성 도구로 전달하도록 변경했습니다.
- Windows 격리 CLI에서 NAS의 매핑 드라이브를 작업 위치로 사용하면 경로 오류가 발생했습니다. 시험용 작업 파일은 로컬에 두었습니다.
- VAS 검사 명령은 UNC로 시작해도 이미 연결된 드라이브를 찾아 npm에 전달하며, 새 드라이브 연결이나 전역 설정 변경은 하지 않습니다.

## 검증 범위

현재 Codex 호스트의 실제 분업과 결과 회수는 확인했습니다. 독립 실행마다 성공을 보장하는 성능 평가나 전체 제품 검사는 아닙니다.
일반 하위 에이전트의 권한은 부모에게서 상속될 수 있습니다. 검토자의 파일 미수정은 해시로 확인했으며 별도 샌드박스를 검증했다고 주장하지 않습니다.
이 PC에서 Claude Code 실행 프로그램을 찾지 못했으므로 Claude 실호출은 미검증입니다.
네이티브 설정 파일은 유지하되, 호스트의 실제 지원 여부가 우선합니다.
