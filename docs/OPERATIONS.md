# 운영 가이드

## 실행

- 일반 사용자: `Run-VAS-System.bat` 더블클릭
- 수동 실행: `powershell -ExecutionPolicy Bypass -File scripts/Start-VAS.ps1`
- 연결한 디자인 작업 열기: `scripts/Start-VAS.ps1 -SessionId ID` (CLI에서 확인한 32자리 세션 ID). 인증값은 실행기가 브라우저에 전달하며 콘솔의 `VAS_READY`에는 출력하지 않습니다. `-NoBrowser`는 서버만 준비하고 인증값이 없는 주소를 출력합니다.
- 연결된 VAS 탭은 인증된 연결 확인 요청으로 로컬 서버를 유지합니다. 모든 연결 탭을 닫고 인증된 API 요청도 없으면 마지막 요청에서 기본 30분 뒤 종료됩니다.
- 인증 없는 `/health` 확인이나 정적 파일 조회는 종료 대기 시간을 연장하지 않습니다. 브라우저가 배경 탭의 요청을 중단하면 열린 탭도 연결 유지가 되지 않을 수 있습니다.

VAS는 기존 프로그램의 폴더 위치만 프롬프트에 넣고 내부는 분석하지 않습니다. 실제 구조·기술 스택·실행 방법은 Codex·Claude·Antigravity가 원본 폴더에서 확인합니다.

기본 화면은 새 작업 지시를 만드는 데만 사용합니다. 결과 불러오기와 RAG 검토 모듈은 호환용으로만 보존합니다.

## 로컬 상태 파일과 실행 인증

- 런타임 파일과 작성 중인 임시 파일은 현재 Windows 사용자·SYSTEM·관리자 그룹만 허용하는 상속 차단 ACL로 보호합니다. 임시 파일은 이 권한으로 먼저 만든 뒤 토큰을 기록합니다. 기존 런타임 파일도 재사용 전에 경로·소유권·권한을 확인합니다. 상위 폴더나 사용자가 지정한 상태 폴더의 ACL은 변경하지 않습니다.
- Windows 작업 기억과 런타임 상태는 실제 로컬 폴더를 사용합니다. 상태 경로의 상위 폴더·파일에 심볼릭 링크·접합점이 있거나 네트워크 드라이브·UNC·장치 경로·대체 데이터 스트림이면 접근을 거부합니다. VAS 제품 소스를 NAS에 두는 것은 가능하며 기본 상태 위치는 이 PC의 `%LOCALAPPDATA%\QUINTPACT\VAS\`입니다.
- 경로 검사나 런타임 파일 권한 적용에 실패하면 기존 자료를 자동 삭제하거나 더 약한 권한으로 재시도하지 않습니다. 링크 대신 실제 로컬 상태 폴더를 지정하거나 해당 사용자의 파일 접근 권한을 확인한 뒤 다시 실행합니다.
- 토큰은 로컬 연결을 위한 평문 인증값이며 암호화된 비밀 저장소가 아닙니다. 같은 사용자 권한으로 실행되는 프로그램과 관리자를 차단하지 않습니다. 파일 경로 검사는 reparse point를 대상으로 하며 하드 링크나 적대적인 동시 교체를 완전히 막는 수단은 아닙니다.
- 브라우저 최초 연결 주소에는 인증값이 포함됩니다. 정상 저장이 가능하면 주소에서 제거하지만 저장 제한 시 fragment로 전달할 수 있으므로 실행 주소를 공유·북마크하거나 화면에 노출하지 않습니다. 콘솔 출력에서 토큰을 제거한 것이 URL 전달 방식을 일회용 인증으로 바꾼 것은 아닙니다.

## 로컬 런타임에 연결되지 않은 경우

BAT에서 로컬 서버 시작에 실패하면 파일을 직접 여는 제한 모드로 전환합니다. GitHub Pages도 로컬 런타임에 연결된 화면이 아닙니다.

| 기능 | 연결되지 않은 화면 |
|---|---|
| 디자인 예시·설정, 요구사항 작성 | 사용 가능 |
| 디자인·초안의 브라우저 저장 | 브라우저 저장 권한이 허용한 범위에서 가능 |
| 폴더 위치 | 직접 입력·붙여넣기 가능, Windows 폴더 선택창은 사용 불가 |
| 프롬프트 복사·인계 JSON 저장 | 사용 가능. 복사 권한이 없으면 표시된 문구를 직접 복사 |
| 대화 세션과 디자인 설정 동기화 | 사용 불가. 로컬 런타임을 실행한 뒤 AI가 연결한 화면에서 진행 |
| Windows 작업 기억·런타임 API | 사용 불가. 브라우저 작업 기억은 해당 브라우저의 동의·저장 설정을 따름 |

디자인을 브라우저에 저장한 것과 대화 세션에 저장한 것은 다릅니다. 화면에서 만든 인계 자료는 [프롬프트 전달 흐름](HANDOFF.md)으로 사용합니다. 이미 VAS에 연결된 대화에서는 “이 설정으로 만들어줘”라고 말하면 AI가 최신 설정·대상을 확인하고 [구현과 검증](CHAT-EXECUTION.md)을 이어갑니다.

## 저장과 복구

- 코어 체크포인트: `.vas_backups/checkpoint_*.zip` 최신 10개
- Windows 작업 기억: `%LOCALAPPDATA%\QUINTPACT\VAS\`
- 브라우저 작업 기억: IndexedDB
- 작업 기억 가져오기: 브라우저와 Windows의 schema 1 형식을 지원하며 같은 ID는 병합합니다. 과거 Windows format/version 내보내기도 브라우저에서 읽습니다.
- Windows 작업 기억은 누적 10,000건과 직렬화한 UTF-8 8 MiB를 상한으로 사용합니다. 초과하는 저장·가져오기는 HTTP 413으로 거부하고 기존 파일을 유지합니다.
- 기존 Windows 파일이 이미 상한을 넘으면 `recoveryRequired`로 표시하고 동작상 동의를 끈 상태로 읽기·추가 저장을 거부합니다. 자동으로 격리하거나 지우지 않습니다. 상한에 도달했거나 이미 넘은 경우에도 기록 끄기와 기억 없이 시작은 가능합니다. 사용자가 전체 삭제를 선택하면 빈 저장소·동의 해제로 초기화됩니다.
- 브라우저 기본 저장소의 기억 가져오기는 한 트랜잭션으로 확정합니다. 실패하면 기존 기록을 유지하고 같은 파일로 다시 시도할 수 있습니다. 외부 사용자 정의 어댑터는 자체 importData 구현의 원자성을 따라야 합니다.
- 기존 프로젝트·가져오기 자료: `workspace/`에 그대로 보존

### Windows 작업 기억의 복구 자료와 임시 파일

현재 기록과 부가 파일은 다음 한도로 관리합니다. 이미 한도를 넘은 파일은 자동으로 지우거나 잘라내지 않습니다.

| 자료 | 한도와 처리 |
|---|---|
| 현재 기록 `memory.json` | 10,000건·8 MiB, 기존 저장 한도 유지 |
| 직전 백업 `memory.previous.json` | 1개·8 MiB, 정상 저장 때 직전 기록으로 교체 |
| 손상 복구 원본 `memory.corrupt-*.json` | 합계 16 MiB·10개, 자동 삭제하지 않음 |
| 남은 `.memory-*.tmp`, `.consent-*.tmp` | 합계 8 MiB·32개, GUID 이름이며 24시간 이상 지난 일반 파일만 자동 정리 |

이 관리 대상의 정상 보관량 합계는 최대 40 MiB이며, 기록 저장 중 새 임시 파일을 포함하면 최대 48 MiB가 필요할 수 있습니다. 작은 동의 설정·런타임 파일과 관련 없는 파일은 이 합계에 포함하지 않습니다. 전체 폴더의 디스크 할당량을 강제하는 기능은 아닙니다.

- 손상 원본은 시간과 임의 식별자가 포함된 서로 다른 이름으로 보관하며 기존 복구 파일을 덮어쓰지 않습니다. 새 원본까지 보관하면 한도를 넘는 경우에는 현재 파일을 옮기지 않고 복구 필요 상태를 알립니다.
- 정상 기록을 읽을 수 있으면 이력 한도를 넘더라도 조회·내보내기와 기록 끄기는 가능합니다. 추가 저장·수정·병합·일시 중지 설정은 `413 memory_history_limit_exceeded`로 거부하고 기존 자료를 보존합니다. 필요한 기록을 내보낸 뒤 명시적으로 삭제하거나 교체 가져오기를 선택해 정리합니다.
- 현재 기록 자체가 손상돼 있고 새 복구 원본을 보관할 공간도 없으면 해당 기록의 조회·내보내기는 불가능합니다. 파일을 별도로 보존한 뒤 전체 삭제로 초기화할 수 있으며, 기록 끄기는 계속 가능합니다.
- 자동 임시 파일 정리는 시작·접근 시 같은 저장 잠금 안에서 수행합니다. 최근 임시 파일, 이름이 다른 파일, 링크 대상은 자동 삭제하지 않습니다. 잠겨 있어 정리하지 못한 파일은 남겨두고 용량에 계속 포함하며 조회나 기록 끄기를 막지 않습니다.
- 명시적인 기록 삭제·교체 가져오기는 예약된 백업·복구·임시 파일을 함께 정리합니다. 먼저 새 기록을 확정하므로 그 쓰기가 실패하면 복구 자료는 그대로 남습니다. 확정 후 부가 파일 정리만 실패한 경우에도 성공으로 표시하지 않으며, 잠금 등을 해제한 뒤 다시 정리해야 합니다.
- 상태 API의 `history`는 안전한 경로의 보관량·개수·한도 초과를 보여줍니다. 관리 경로가 링크이거나 파일 유형이 맞지 않으면 조회도 거부하며 `503 memory_path_invalid`로 알립니다. `unsupportedPaths` 필드는 정상 경로에서 호환을 위해 `false`로 유지합니다. 이는 모든 파일 경합이나 권한 공격을 차단한다는 의미는 아닙니다.

잘못된 가져오기 방식은 `400 invalid_memory_mode`, 잘못된 공통 JSON 본문은 `400 invalid_json`, 5 MiB를 넘는 공통 API 본문은 `413 request_body_too_large`로 알립니다. 인증 검사는 먼저 수행하며 대화 API의 별도 64 KiB 한도는 유지합니다.

## 개인정보

- 기본값은 작업 기억 사용 안 함입니다.
- 동의 전 이벤트를 기록하지 않습니다.
- Windows 서버는 기록 데이터와 별도인 `memory-consent.json`의 동의를 확인하며 미동의 상태의 이벤트 저장·가져오기를 거부합니다. 동의 설정 파일이 없는 과거 저장소는 기존 기록을 보존하고 미동의로 시작합니다. 기록 파일·가져오기 파일의 동의 값은 허용 근거로 사용하지 않습니다. 브라우저 IndexedDB의 동의·저장 설정은 별개입니다.
- 정상 크기의 Windows 저장소는 동의를 철회해도 기존 기록의 조회·내보내기·삭제가 가능합니다. 일시 중지는 자동 기록을 멈추며, 동의가 유지된 상태에서 사용자가 직접 요청한 가져오기는 가능합니다.
- 설정에서 사용·중지·삭제·전체 초기화를 언제든 실행할 수 있습니다.
- 비밀값, 파일 내용, 절대 경로, 파일명은 작업 기억에 저장하지 않습니다.
- JSON 항목 이름도 값과 같은 개인정보 검사를 거칩니다. 과거 기록은 내보낼 때 다시 정제하지만 기존 디스크 원본을 자동으로 지우지는 않습니다.
- 최종 JSON에는 연락처와 작업 기억 원본을 넣지 않습니다.
- 사용자가 고른 폴더 위치는 복사 프롬프트에만 사용하고 JSON·작업 기억·선택 기록 파일에는 저장하지 않습니다.
- 새 신청서 초안은 기본적으로 브라우저 localStorage에 저장되며 복원 버튼으로 불러옵니다. JSON 저장 뒤 삭제하지만 프롬프트 복사만으로는 삭제하지 않습니다. 작업 기억 동의와 별도인 현재 입력 복구 기능입니다.
- 기존 프로그램 화면의 현재 폴더 위치와 입력은 같은 탭의 history.state로 복구합니다. 공유하는 JSON에는 폴더 위치를 넣지 않습니다.
- 디자인 미리보기나 신청서 답변은 추천 기억으로 기록하지 않습니다. 동의한 경우 최종 복사·저장·디자인 적용 때 확정한 디자인만 기록합니다.
- 이전 버전의 확정 여부가 표시되지 않은 기록과 검색 기록은 새 디자인 추천에서 제외하며 원본 기록은 유지합니다.
- 영구 저장소 쓰기·삭제 실패는 성공으로 표시하지 않습니다. 브라우저 최초 저장소 초기화가 불가능하면 현재 화면의 임시 저장임을 표시합니다.
- 초안 자동 저장·설정 변경·삭제 실패는 화면에 표시합니다. JSON 다운로드 성공과 초안 삭제 실패는 각각 안내하며 삭제 버튼으로 재시도할 수 있습니다.
- 인증 헤더는 방식에 관계없이 전체 값과 접힌 후속 줄을 제외하고, URL authority의 사용자 정보도 제외합니다. 인증 헤더와 같은 줄에 이어 쓴 설명은 함께 제외될 수 있으므로 정상 요구사항은 다음 줄에 적습니다.
- 인계와 작업 기억은 알려진 비밀값을 검사할 때 Unicode·hex escape, ASCII percent, 일부 HTML entity를 최대 두 번 해석하고 정적 문자열 결합을 확인합니다. 코드를 실행하지 않으며, 정상 URL·JSON·디자인 토큰은 원문을 보존합니다. 변형된 표현에서 민감 정보가 발견되면 해당 문자열 전체가 제외될 수 있습니다.
- 정제는 알려진 형식에 대한 보호입니다. 임의 암호화·무한 중첩 인코딩·실행 결과로 만들어지는 값·표식 없는 비밀값을 모두 판별하지는 않습니다. 자동 정제 표시를 보안 검사 통과로 해석하지 말고 공유 전 결과를 확인합니다.
- 전체 초기화는 현재 화면·URL·열린 탭의 디자인과 추천도 기본값으로 되돌립니다.

## 검증

```powershell
npm.cmd run knowledge:check
npm.cmd run test:python
npm.cmd run test:browser
npm.cmd run test:package
```

`npm.cmd run test:release`의 10회 반복은 명시적 요청 때만 실행합니다.

## 배포

`npm.cmd run release:build` 후 `dist/SHA256SUMS.txt`와 ZIP의 `manifest.json`을 확인합니다. `.git`, `workspace`, 백업, 캐시, 환경 변수, 작업 기억은 배포에서 제외합니다.
