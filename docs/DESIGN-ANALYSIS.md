# 참고 이미지로 디자인 분석·적용하기

프로젝트 배포본의 개발 미리보기에는 `design-analysis` 스킬이 기본 포함됩니다. 별도 설치·Obsidian 연결·API 키 없이 코딩 AI의 이미지 보기와 구현 도구를 사용합니다. VAS 자체가 이미지를 인식하거나 AI로 자동 전송하는 기능은 아닙니다.

## 사용

프로젝트 폴더를 코딩 AI에서 열고 참고 이미지를 채팅에 첨부한 뒤 “이 디자인 요소를 참고해서 재고 앱을 만들어줘”처럼 요청하세요. 현재 대화에서 이미 볼 수 있는 이미지는 다시 첨부할 필요가 없습니다. 이미지를 분석해 달라고만 하면 분석까지만 진행합니다.

AI는 실제 이미지의 글꼴·색상·배치·이미지 표현·여백을 읽고 각각을 앱의 어느 부분에 적용할지 정리합니다. 구현을 요청했다면 분석표에서 멈추지 않고 코드에 적용하고 화면을 비교합니다. 샘플의 요금제·결제·업종별 기능은 요청 없이 따라 만들지 않습니다.

예: “큰 제목과 가는 본문(관찰) → 재고 현황/품목 입력에 위계 적용 → 제목 크기는 앱에서 정한 제안값 → 실제 화면과 한글 글꼴 확인”처럼 관찰부터 적용까지 연결합니다. 폰트명·정확한 색상값은 측정 근거 없이 단정하지 않습니다.

| 확인 단계 | 남기는 내용 |
| --- | --- |
| 원본 확인 | R1 등 참조 ID, 실제 본 이미지·판본·영역, 미열람 부분 |
| 5요소 분석 | 관찰 근거, 요소 사이의 관계, 추정·실측 구분 |
| 앱 대응 | 실제 화면·컴포넌트·토큰에 적용할 선택과 위치 |
| 구현 확인 | 실제 화면·동작·글꼴 로딩과 남은 차이 |

이미지 파일명·링크·첨부 개수만 전달되면 열람했다고 표시하지 않습니다. 이미지가 없거나 호스트가 볼 수 없으면 필요한 원본만 요청하고 확인 가능한 작업부터 진행합니다. VAS의 신청 폼 파일 선택은 기존처럼 개수만 인계하며 이미지 내용은 전달하지 않습니다.

## 기본 탑재 경로

- Windows 프로젝트 ZIP: 루트 `.agents/skills/design-analysis/SKILL.md`, Claude용 `.claude/skills/design-analysis/SKILL.md`. 도구 정본은 `.vas/.agents/skills/design-analysis/SKILL.md`이며 같은 내용입니다.
- 루트 시작 지침이 참고 이미지 작업에 스킬을 연결합니다. 호스트의 자동 스킬 탐색만 믿지 않습니다.
- 브라우저 프롬프트·독립 폼·대화 `prepare`에는 활성 디자인의 분석 지침 본문을 함께 전달합니다. 외부 프로젝트에 복사해도 별도 스킬 파일을 먼저 설치할 필요가 없습니다.
- 네이티브 Designer 지침도 같은 본문을 포함합니다. 실제 역할 호출 가능 여부는 코딩 호스트에 따릅니다.

기존 디자인 유지에서는 새 스타일 분석을 강제하지 않고, 부분 수정은 지정한 요소에만 적용합니다. 사용자 지정 토큰을 이미지 추정값으로 덮어쓰지 않습니다. 최신 사용자 지시가 이전 선택을 바꾸면 그 범위를 반영합니다.

위임할 때 같은 분석·요구사항·원본을 전달합니다. 원본을 받을 수 없는 에이전트는 요약만 전달받았음을 구분합니다. 재개 시 확인한 분석·선택은 기존 진행 요약으로 이어받되 원본이나 요청이 달라지면 영향받은 관찰을 다시 확인합니다. 별도 이미지 저장소를 만들거나 원본을 외부로 업로드하지 않습니다.

스킬 탑재와 프롬프트 전달은 실제 이미지 분석·화면 검증과 다릅니다. 지정 폰트의 선언과 로딩도 구분합니다. 모바일 원본이 없으면 모바일 배치는 구현 제안이며 원본 모바일과 일치한다고 주장하지 않습니다.

## 실제 화면 검수

PC·모바일 폭에서 빈 화면, 실제 입력, 긴 한글과 큰 숫자를 확인합니다. 320 CSS px처럼 좁은 폭에서도 글자·버튼의 잘림과 겹침을 살피고, 입력·키보드 포커스·새로고침을 직접 실행합니다. 브라우저 폭 조절은 실제 휴대전화 확인과 구분합니다.

선택 스타일의 폰트 파일이 배포본에 있으면 필요한 파일과 라이선스를 앱 자산으로 복사해 연결합니다. `.vas`의 도구 경로에 앱이 의존하게 만들지 않습니다. 라틴·숫자에 지정 글꼴이 쓰이는지와 한글에 어떤 대체 글꼴이 쓰이는지를 각각 확인합니다. 파일이 없거나 로딩되지 않으면 정확한 글꼴 적용으로 표시하지 않습니다.

작은 보조 글자와 placeholder도 실제 배경 위에서 대비를 측정합니다. 장식에 적합한 색이 작은 글자에 적합한 것은 아니므로, 허용 범위에서 글자용 색을 별도로 정하고 수정한 화면을 다시 확인합니다. 확정 토큰을 임의로 바꾸지는 않습니다. 기준은 W3C WCAG 2.2의 글자 대비(SC 1.4.3)와 좁은 화면 재배치(SC 1.4.10)입니다.

호스트가 직접 확인한 결과와 별도 검증자가 확인한 결과를 구분합니다. 미실행 항목을 성공으로 표시하지 않으며, 한 사례의 통과를 모든 호스트·참고 이미지의 성공으로 확대하지 않습니다.
